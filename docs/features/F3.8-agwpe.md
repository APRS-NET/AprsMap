# F3.8 AGWPE TNCs as sources

Status: proposed for 0.8.0 ([#384](https://github.com/APRS-NET/AprsMap/issues/384)); waiting on APRS.NET's AGWPE client
connection ([APRS.NET#225](https://github.com/APRS-NET/APRS.NET/issues/225), under #224, gap G22). Nothing is built
until it ships.

## User story

My sound-card modem (Dire Wolf, UZ7HO SoundModem, or AGWPE itself on an older Windows PC) offers the AGWPE network
interface, and on some set-ups nothing else. I add it in Settings › Sources by its address, pick the radio port from the
list it gives, and its packets join the map and lists as a KISS TNC's do. With a licensed profile and Transmit on, my
beacons and messages go out through it.

## Background: what already exists

- KISS TNCs as sources, over TCP and serial (F3.1): host and port, the TNC port, the pill with its switch and
  Reconnect now, *heard here* markers and RF paths (F3.3), the quiet warning (#378), and the Source console (F1.28).
- Transmitting through a TNC (F2.1, F2.2): a licensed profile that isn't receive only, the Transmit switch, the
  library's transmit limit; on a gateway, only an authenticated operator. Never an emergency beacon.
- The master source list (F1.25): profiles pick from it; every packet carries its source; a copy heard on another
  source adds to Seen on.

## Behavior

1. **A new source kind, AGWPE over TCP**, in Settings › Sources beside KISS over TCP and serial: a name, the host and
   port (**8000** by default), and the **radio port**. The radio port is picked from the list the AGWPE server gives,
   each with its description ("Port1 Dire Wolf on soundcard 0"), with **Refresh** to ask again; it can be typed when
   the server can't be reached yet. The profiles that use it are ticked as for a KISS TNC.
2. **Receiving**: the frames heard on that radio port join the same pipeline as a KISS TNC's, as raw AX.25 (decision
   2), so paths, the H bits and *heard here* (F3.1 behavior 8, F3.3) work as they do for KISS. Frames from the server's
   other radio ports are left out. Another radio port is another source (decision 1).
3. **Transmitting**, gated exactly as a KISS TNC is (F2.1): a licensed profile, not receive only, the Transmit switch,
   the transmit limit, and on a gateway an authenticated operator; sent as raw frames on the chosen radio port.
   Beacons and messages offer it under **Send via** as any TNC (F2.2). Never an emergency beacon.
4. **State and health**, as KISS over TCP: the pill (connecting, connected, reconnecting with the wait and why), its
   switch and Reconnect now; the dashboard's Connection tile; the quiet warning after 30 minutes without a frame
   (#378); and the Source console's traffic (F1.28), showing each AGWPE frame's kind and the AX.25 frames in it.
5. **Version and ports at connect**: on connecting, the source asks the server's version and its radio ports, and the
   console and the source's settings show them. A radio port the server no longer lists is reported on the pill
   ("Port 2 isn't on this server") rather than staying silent.
6. **On a gateway** it's a source like any other, set up by the operator; `docs/deployment.md` says how to reach a
   modem on the gateway's PC (`localhost:8000`) or another machine, and that Dire Wolf's AGW port is on by default.
7. **When to choose it**: the docs and the source's help say to prefer KISS over TCP where the modem offers both, as
   Dire Wolf and SoundModem do (one protocol fewer, and the transmit path is the same); AGWPE is for set-ups that offer
   only it.

## Service surface

- `SourceKind.Agwpe`, with `SourceSettings.Host`, `Port` and `AgwPort` (the radio port, from 0); validated as KISS over
  TCP's are, with `settings.source.agwpe-invalid`.
- `IEngineService.GetAgwpePortsAsync(string host, int port)` → the server's radio ports with their descriptions, for
  the picker; the operator's only on a gateway, as the serial port list is.
- `SourceStatus` as for KISS TNCs; the console's lines gain the AGWPE frame kind.

## APRS.NET dependencies

G22, the AGWPE TCP transport ([APRS.NET#224](https://github.com/APRS-NET/APRS.NET/issues/224); the connection is
[#225](https://github.com/APRS-NET/APRS.NET/issues/225)): connecting with reconnects and the dead-link timeout as
`KissTcpConnection` has; the version and port list; monitoring raw frames on one radio port; sending raw frames; and,
if it offers one, the quiet event. Protocol framing and AX.25 decoding stay in APRS.NET; AprsMap only adds the source.

## Desktop vs web differences

None in behaviour. On a gateway, the host is reached from the gateway's computer, so `localhost` means the gateway's.

## Acceptance tests

1. Against a fake AGWPE server: the source connects, asks the version and the ports, and the picker lists them.
2. Frames on the chosen radio port are listed with the source's name and *heard here*; frames on another port aren't.
3. With Transmit on and a licensed profile, a beacon goes out as a raw frame on that port; with Transmit off, or as a
   gateway viewer, nothing is sent.
4. The server closing the connection: the pill says reconnecting with the wait, and the source comes back.
5. A radio port the server stopped listing is reported on the pill.
6. Manual: a local Dire Wolf with null audio, receiving and transmitting through its AGW port.

## Decisions for review

1. **One radio port per source** (proposed): a server with two radios is two sources, each with its own name, pill and
   Send via choice, as two KISS TNCs would be. One source for several ports, counted per port, can follow.
2. **Raw frames, not the server's monitor text** (proposed): AGWPE can give monitored frames as text or as raw AX.25;
   raw keeps paths, H bits and the third-party header exact and goes through the same decoder as KISS.
3. **Connected mode is out of scope** (from #384): no keyboard-to-keyboard sessions; AGWPE over anything but TCP is
   out too.
4. **Prefer KISS where offered** (proposed), said in the docs and the source's help rather than enforced.
