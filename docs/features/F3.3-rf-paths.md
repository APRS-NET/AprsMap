# F3.3 Per-port RF paths and RF versus IS attribution

Status: built for 0.5.0 ([#210](https://github.com/APRS-NET/AprsMap/issues/210)). Much of it arrived with F2.1, F2.2
and F3.1; this spec records what's there and adds what's left: seeing how my own packets got out.

## User story

As an operator sending on RF and APRS-IS, I set the path each radio port uses, my beacons go out on each, and the map
and details show me how my last position actually got around: which digipeaters repeated it, which IGates gated it,
and what reached APRS-IS straight from me.

## Background: what already exists

- **Per-port path** (F2.1 behavior 5.2): each TNC that isn't RX only has its own TX path, `WIDE1-1,WIDE2-1` unless set.
- **Beacons on RF and APRS-IS** (F2.2): position and status beacons go out on every source ticked in Send via, each with
  that source's path; Send position now and Test send per source.
- **Heard here** (F3.1 behavior 8): packets from a TNC are marked heard by this station, directly or through
  digipeaters, and routes end at this station.
- **Test send** (F2.1 behavior 9) already listens for its packet coming back and names the digipeater or IGate that
  carried it.

## Behavior

### My packets coming back

1. Every position, status or object this station sends is **followed for 10 minutes** (decision 1): each copy heard
   back is recorded with how it came: repeated by a digipeater on RF (heard on my TNC, with the digipeater that marked
   itself), gated to APRS-IS by an IGate (an APRS-IS copy whose path carries the IGate's q-construct), or sent to
   APRS-IS by me (my own APRS-IS send).
2. **This station's details** (F3.1's "this station" in Details) gain **My last position**: when it went out, on which
   sources, and how it was heard back: "Repeated by N0DIG-1 (RF), gated by N0IGT (to APRS-IS), sent to APRS-IS
   directly". With nothing heard back over RF within 10 minutes it says so: "Not heard back on RF".
3. **On the map**, selecting this station draws the last position's **routes out**: from my house to each digipeater
   that repeated it (solid) and on to each IGate that gated it (dotted), in the same style as F1.21's routes, with RF and
   APRS-IS told apart by line style and a legend, never by colour alone.
4. The **status bar's** transmit tip adds "Last beacon heard back via N0DIG-1, 3 min ago" when there is one.

### Paths

5. Settings › Sources keeps each TNC's TX path (F2.1); its help says what a path does and that APRS-IS sends have none.
   A path that can't be sent is refused when saved, as today.
6. Beacons use each source's path; no per-beacon path (decision 2).

## Service surface

- `TransmitStatus` and `ThisStation` gain `LastPosition` (`LastPositionHeard`): the last position's time, sources and
  the copies heard back (`HeardBack`: kind digipeated, gated or direct; by whom; when).
- `GetRoutesOutAsync`: this station's last position's routes out, one `PacketRoute` (F1.21's) per copy heard back over
  RF or gated, from where it was sent. An RF copy's route ends at the digipeater, not back at this station.
- The legend is a line in My last position, shown while routes are drawn: "a solid line with an arrow is a repeat on
  RF; a dotted line is the IGate that put it on APRS-IS".
- No new error codes.

## APRS.NET dependencies

- **G20** (delivered): q-construct and path analysis, which F1.21 and Test send already use to tell a digipeater from an
  IGate.

## Desktop vs web differences

None; on a gateway it shows to every viewer, like the rest of the station's details.

## Acceptance tests

1. A beacon sent on a TNC and APRS-IS, then heard back from a digipeater on the TNC and from an IGate on APRS-IS, shows
   both in My last position and draws both routes.
2. A beacon heard back on nothing within 10 minutes says "Not heard back on RF".
3. RF and APRS-IS legs are told apart by line style in every palette, and the legend says which is which.
4. Each TNC's beacon goes out with that TNC's path.

## Decisions for review

1. **Followed for 10 minutes** (proposed): long enough for a slow digipeater chain and an IGate, short enough not to
   confuse it with the next beacon.
2. **The path is per source, not per beacon** (proposed): one less setting, as F2.1 already does.
