# F2.1 Own station and transmitting

Status: engine, contract and gateway built for 0.5.0 ([#190](https://github.com/APRS-NET/AprsMap/issues/190)); the
UI follows.

## User story

As a licensed operator, I tell the app who my station is (callsign, symbol and comment) and turn transmitting on
myself, once the app has checked I can. Nothing goes out until I do. The first thing I send is my position, by hand,
so I see exactly what the network will see before anything is sent automatically.

## Background: what already exists

- Each profile has a callsign with SSID, a passcode (or -1 to log in receive-only), a location and its sources (F0.4,
  F1.25). The setup wizard refuses `N0CALL` and `NOCALL` and offers the passcode calculator only for the user's own
  callsign (F0.5).
- The status bar shows an eye beside the APRS-IS pill when the login isn't verified (receive-only).
- Nothing transmits: APRS-IS logs in to receive; KISS sources (F3.1) never send.

## Behavior

### Who the station is

1. **Symbol**: each profile has an APRS symbol, the table or overlay character and the symbol code (`/-`, a house, for a
   new profile). It's drawn for the station on the map and sent in its positions.
2. **Comment**: each profile has an optional position comment, at most 43 characters (the most an uncompressed position
   without a data extension carries, APRS101 chapter 8), in printable ASCII. Longer or other text is refused on save
   with `settings.profile.comment-invalid`.
3. **SSID guidance**: beside the callsign, the UI says what the common SSIDs mean (none for a home station, `-9` for a
   car, `-7` for a handheld, `-10` for an internet-only station, and so on, from the APRS SSID recommendations). It's
   guidance only; any SSID APRS.NET accepts is allowed.

### The Transmit switch

4. **Transmit** is a quick toggle (F1.15), saved with the others, and **off** for every new and existing station.
5. Turning it **on** is refused, with a code the UI translates, unless every one of these holds:
   1. the engine wasn't started receive-only (`Engine:ReceiveOnly`, F1.26): `transmit.receive-only`;
   2. the callsign isn't a placeholder (`N0CALL`, `NOCALL`, any SSID): `transmit.placeholder-callsign`;
   3. the active profile has an APRS-IS source and APRS-IS is switched on: `transmit.no-aprs-is`;
   4. APRS-IS is connected (`transmit.not-connected`) and the server **verified** the login (`transmit.not-verified`),
      which means the passcode belongs to the callsign. A licensed callsign on RF without APRS-IS comes with Phase 3.
6. Turning it **off** always works, at once.
7. **Switching the active profile turns Transmit off**: the consent was for that callsign.
8. Once on, the engine checks the same conditions before **each** send. While one fails, the switch stays on, nothing
   is sent, and the status says why (`EngineStatus.Transmit.Blocked`); a dropped connection is the usual case, and
   sending resumes when the login is verified again.
9. **On a gateway**, transmitting needs a signed-in operator (F2.9), which doesn't exist yet: every browser is refused
   Transmit and sending with `gateway.operator-only`, even when `AllowSettingsChanges` is on.

### Sending a position by hand

10. **Send position now** sends one position report for the active profile:
    1. as the profile's callsign, to the TOCALL from `Brand.Tocall`, with no path (APRS-IS adds the q-construct);
    2. the profile's location, uncompressed, without a timestamp, with its symbol and comment, as a station without
       messaging (`!`; F2.4 changes it to `=` once the app answers messages);
    3. built with APRS.NET's `PacketAddress` and sent with its connection's `SendAsync`.
11. It's refused when Transmit is off (`transmit.off`), when a condition of behavior 5 fails (that condition's code),
    and when the profile has no location (`transmit.no-position`). A send that fails on the connection reports
    `transmit.failed`.
12. **The interlock**: automatic transmissions (beacons, F2.2) wait until a position has been sent by hand for the
    profile's current callsign and location. The engine records that on the profile (`PositionConfirmed`) and clears
    it when the callsign, symbol, comment or location changes; F2.2 reads it.
13. **What was sent is shown as ours**: the packet goes into the packet list marked `Sent`, from the APRS-IS source, and
    into the station store, so the station appears on the map as the network will see it. `EngineStatus.Transmit`
    records when the last packet was sent.

## Service surface

- `StationProfile` gains `Symbol`, `Comment` and `PositionConfirmed`.
- `StationToggles` gains `Transmit` (default off); `Toggle` gains `Transmit`.
- `EngineStatus` gains `Transmit` (`TransmitStatus`: `On`, `Blocked`, `LastSent`, `ReceiveOnly`).
- `IEngineService.SendPositionAsync()` returns the `PacketView` sent; hub method `SendPosition`.
- `PacketMarkers.Sent`.
- Error codes `transmit.*` (an operation failure) and `settings.profile.comment-invalid`,
  `settings.profile.symbol-invalid`.
- `EngineOptions.ReceiveOnly` (the refusal and the status; F1.26 adds the unverified login).

## APRS.NET dependencies

G01 (`PacketAddress`, `PositionReport`, the encoders) and G02 (`AprsIsConnection.SendAsync`, which refuses an unverified
login itself): delivered. No blocker.

## Desktop vs web differences

| | Desktop | Web (gateway) |
| --- | --- | --- |
| Transmit and Send position now | The user, after the checks | Refused until F2.9's operator sign-in |
| Receive only | `Engine:ReceiveOnly` in `appsettings.json` | Environment variable |

## Acceptance tests

1. Transmit is off in new settings and in settings stored before this feature.
2. Turning it on is refused with the right code for each failing condition of behavior 5, and allowed when all hold;
   off always works; switching profiles turns it off.
3. Send position now, with Transmit on and a verified login, writes one packet
   `CALL>TOCALL:!DDMM.mmN/DDDMM.mmW-comment` to APRS-IS; the packet list shows it marked `Sent`; the station store has
   the station; the profile is marked `PositionConfirmed`, and changing its location clears it.
4. With Transmit on and the connection dropped, sending is refused with `transmit.not-connected` and the status says so.
5. On the gateway, `SetToggle(Transmit, true)` and `SendPosition` are refused with `gateway.operator-only`, with
   `AllowSettingsChanges` on and off.
6. A comment over 43 characters, or with a non-ASCII character, and a symbol that isn't two printable characters, are
   refused on save.

## Decisions for review

1. **Transmit is a quick toggle** (proposed), saved with the others, so a station that was transmitting keeps
   transmitting after a restart, held by the checks in behavior 8 and by the interlock for automatic sends.
2. **A dropped or unverified login holds sending without turning Transmit off** (proposed), so a short outage doesn't
   need the user; switching profiles does turn it off.
3. **`!` until messaging exists** (proposed): `=` would tell others the station answers messages.
4. **The gateway refuses transmitting outright until F2.9** (proposed), rather than trusting `AllowSettingsChanges`.
5. **The interlock is cleared by a change to what's sent** (proposed): callsign, symbol, comment or location.
