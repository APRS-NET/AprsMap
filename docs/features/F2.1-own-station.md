# F2.1 Own station and transmitting

Status: built for 0.5.0 ([#190](https://github.com/APRS-NET/AprsMap/issues/190)), revised 2026-10-17 for
transmitting on several sources. In the UI: Transmit, Send position now and Send position on APRS-IS only in the
connection menu (Ctrl+T), Send position now in each TX-enabled TNC's pill menu, a Transmitting or Transmit held marker
in the status bar, the Sent marker in the packet list; on the profile editor's first step I'm a licensed amateur radio
operator (unticked: a listener ID; ticked: the callsign and Disable TX on this profile), the symbol and the comment; in Settings › Sources, TX enabled and the
TX path on each source, and Test send with what came of it. The listener ID comes from APRS.NET (`AprsIsLogin`,
`0.4.0-alpha.3`), and a listener ID's APRS-IS login is listen-only, so APRS.NET refuses to send on it too.

## Revision proposed 2026-10-18 (for review)

Using the AppImage, the maintainer had a source TX enabled, a licensed profile and Transmit on, and still couldn't
send: the source's pill was switched off, and nothing said so where the message was being written. There are too many
switches. Chosen by the maintainer (2026-10-18): **one switch, and RX-only sources**. Replacing behaviors 4.2, 5,
6's placement, 9 and 10's pill menus:

1. **Disable TX on this profile goes.** A profile that only listens is an unlicensed one (behavior 4.1), and switching
   profiles already turns Transmit off. A stored profile with Disable TX ticked loads with Transmit off.
2. **TX enabled goes; RX only replaces it.** Every source may send unless it's marked **RX only**, a checkbox in
   Add a source (also when the wizard's Add APRS-IS or Add a TNC opens it) and in the source's editor, unticked by
   default. It's for a Direwolf without a transmitter, a scanner, or an APRS-IS server used only to listen; such a
   source is never sent on, whatever the Transmit switch says, and its row and pill say "RX only". A radio's APRS mode is
   no longer a kind of its own (F3.2's revision): it's KISS over serial with RX only. Stored sources load as may-send: the Transmit switch is still off, and turning it
   on is still the user's act.
3. **One Transmit switch, in the status bar**, left of the source pills, in the pills' style: off, on (Transmitting,
   with the next beacon as now), or held (amber, with the reason). Station › Transmit mirrors it, as every menu entry
   mirrors a control (F1.29 behavior 3). It leaves the connection menu (Ctrl+T) and Settings.
4. **Every refusal names what to change and where**, with the source's name: "10.10.20.144 is switched off. Turn it
   on in the status bar.", "Transmit is off. Turn it on in the status bar.", "APRS-IS didn't verify NZ0P-10's
   passcode. Check it in Settings › Sources." The Messages panel, the Beacons section, Test send and the Transmit
   switch's tooltip use the same words.
5. **Test send** stays on each source's row, and with Transmit off its reason has a **Turn Transmit on** button.
6. **Send position now** stays in the Station menu (every source that can send) and each source's pill menu (that one).

Decision 6 below becomes: **one switch over the sources that aren't RX only** (maintainer, 2026-10-18), the
licence confirmation on the profile as decision 8.

## User story

As a licensed operator, I tell the app who my station is (callsign, symbol and comment) and turn transmitting on
myself, once the app has checked I can. Nothing goes out until I do. The first thing I send is my position, by hand,
so I see exactly what the network will see before anything is sent automatically.

## Background: what already exists

- Each profile has a callsign with SSID, a passcode (or -1 to log in receive-only), a location and its sources (F0.4,
  F1.25). The setup wizard refuses `N0CALL` and `NOCALL` and offers the passcode calculator only for the user's own
  callsign (F0.5).
- The status bar shows an eye beside the APRS-IS pill when the login isn't verified (receive-only).
- Before this feature nothing transmitted: APRS-IS logged in to receive, and KISS sources (F3.1) only listened.

## Behavior

### Who the station is

1. **Symbol**: each profile has an APRS symbol, the table or overlay character and the symbol code (`/-`, a house, for a
   new profile). It's drawn for the station on the map and sent in its positions.
2. **Comment**: each profile has an optional position comment, at most 43 characters (the most an uncompressed position
   without a data extension carries, APRS101 chapter 8), in printable ASCII. Longer or other text is refused on save
   with `settings.profile.comment-invalid`.
3. **SSID guidance**: beside the callsign, the UI says what the common SSIDs mean (none for a home station, `-9` for a
   car, `-7` for a handheld, `-10` for an internet-only station, and so on, from the APRS SSID recommendations). It's
   guidance only; any SSID APRS.NET accepts is allowed.

### Who may transmit, and where

Three layers, all of which must allow a send (decided by the maintainer, 2026-10-17):

4. **The profile** may transmit only when all of these hold, on every source alike:
   1. **Licensed**: the profile was saved with I'm a licensed amateur radio operator ticked (`transmit.not-licensed`).
      It covers APRS-IS too: packets sent to APRS-IS can be gated to RF.
   2. **Not disabled**: **Disable TX** is unticked (`transmit.profile-disabled`). It's for a receive-only profile even
      with a licensed operator.
   3. The callsign isn't a placeholder (`N0CALL`, `NOCALL`, any SSID; `transmit.placeholder-callsign`).

   The profile editor's first step asks this with **one checkbox**, **I'm a licensed amateur radio operator**
   (maintainer, 2026-10-17):
   1. **Unticked**, a new profile's default: the profile listens only. There's no callsign field and no passcode step;
      the profile gets a generated **listener ID**, `SWL` and six random digits, such as `SWL482913` (nine characters,
      the most an APRS-IS login takes; it ends in digits, so it can't be anyone's amateur callsign, and it's random, so
      two listeners don't share a login). It logs in to APRS-IS without a passcode, which servers allow for listening,
      listens to TNCs, and every send is refused (`transmit.not-licensed`).
   2. **Ticked**: the callsign field and the SSID guidance appear, and then **Disable TX on this profile**. The profile is
      saved Licensed; unticking the box again brings the listener ID back and clears Disable TX.
   3. A profile made before this checkbox, with a callsign, opens with it ticked: the editor only took callsigns then.
   4. The app never suggests a passcode for a callsign that isn't the user's own; the passcode calculator keeps its own
      confirmation, asked each time it opens.

5. **Each source**: every source has a **TX enabled** checkmark, off for every new and existing source. A source without
   it is never sent on (`transmit.source-disabled`): a Direwolf set up to receive only, a TNC without a radio keyed, or
   an APRS-IS server used only to listen. Each kind adds its own condition:
   1. **APRS-IS**: connected (`transmit.not-connected`), and the server **verified** the login
      (`transmit.not-verified`), which means the passcode belongs to the callsign.
   2. **KISS TNC**: connected (`transmit.not-connected`). Sent with the source's **TX path**, `WIDE1-1,WIDE2-1` by
      default (a list of digipeater aliases or callsigns, checked by APRS.NET); F3.3 adds per-beacon paths. Nothing on
      RF verifies a licence: the profile's confirmation (behavior 4.1) is what allows it.
6. **The Transmit switch**: a quick toggle (F1.15), saved with the others, **off** for every new and existing station:
   the master switch over everything the station sends.
   1. Turning it **on** is refused unless the engine wasn't started receive-only (`Engine:ReceiveOnly`, F1.26,
      `transmit.receive-only`), the profile may transmit (behavior 4), and at least one of the profile's sources may
      send now (behavior 5; otherwise the first source's reason, or `transmit.no-source` when none is TX enabled).
   2. Turning it **off** always works, at once.
   3. **Switching the active profile turns it off**: the consent was for that callsign.
7. **Held, not off**: once on, the engine checks each source before **each** send. A source that can't send now is
   skipped and reported; when none can, nothing is sent, the switch stays on, and the status says why
   (`EngineStatus.Transmit.Blocked`). Each source's pill and its settings row say whether it can send, and why not
   (`SourceStatus.Transmit`). A dropped connection is the usual case; sending resumes when it's back.
8. **On a gateway**, transmitting needs a signed-in operator (F2.9), which doesn't exist yet: every browser is refused
   Transmit, sending and Test send with `gateway.operator-only`, even when `AllowSettingsChanges` is on.

### Test send

9. Each source's settings row has **Test send**, offered only when every layer allows sending: the Transmit switch is
   on, the source is TX enabled and the profile may transmit (otherwise `transmit.off`, `transmit.source-disabled` or
   `transmit.profile-disabled`, and the row says which to change):
   1. it sends one status report, `>` followed by the product name and "test", as the profile's callsign, on that
      source alone (with its TX path on RF);
   2. the row then says it was sent, or why it couldn't be (the codes above, or `transmit.failed`);
   3. for 30 seconds the engine watches every source for the packet coming back (a digipeater repeating it on RF, or
      an IGate gating it to APRS-IS) and the row adds where it was heard, such as "heard back through K0HQ-1", or
      "not heard back" (expected without a digipeater or IGate in range);
   4. it's listed in the packet list marked `Sent`, like any packet the station sends.

### Sending a position by hand

10. **Send position now** sends one position report for the active profile, on **every source that can send now**:
    1. as the profile's callsign, to the TOCALL from `Brand.Tocall`: with no path to APRS-IS (the server adds the
       q-construct), with the source's TX path on a TNC;
    2. the profile's location, uncompressed, without a timestamp, with its symbol and comment, as a station without
       messaging (`!`; F2.4 changes it to `=` once the app answers messages);
    3. built with APRS.NET's `PacketAddress` and sent with the connection's `SendAsync`.
    Beacons (F2.2) and messages (F2.4) choose their sources themselves ("Send via"), from the sources that may send.
    **On one source**: each source's status pill menu (the APRS-IS pill's and every TNC's) has **Send position now**
    for that source alone, shown when the source is TX enabled and offered when it can send now; it's refused for the
    same reasons, with that source's.
11. It's refused when Transmit is off (`transmit.off`), when no source can send (the reasons above), and when the
    profile has no location (`transmit.no-position`). A source whose send fails reports `transmit.failed`; the others
    still send. The result says which sources it went out on.
12. **The interlock**: automatic transmissions (beacons, F2.2) wait until a position has been sent by hand for the
    profile's current callsign and location. The engine records that on the profile (`PositionConfirmed`) and clears
    it when the callsign, symbol, comment or location changes; F2.2 reads it.
13. **What was sent is shown as ours**: each copy goes into the packet list marked `Sent`, with the source it went out
    on, and into the station store, so the station appears on the map as the network will see it.
    `EngineStatus.Transmit` records when the last packet was sent.

## Service surface

- `StationProfile` gains `Symbol`, `Comment`, `PositionConfirmed`, `Licensed` and `DisableTransmit`.
- `IEngineService.NewListenerIdAsync()` returns a fresh listener ID (the engine makes it, so the desktop and web are the
  same).
- `SourceSettings` gains `Transmit` (TX enabled) and, for a TNC, `TxPath`.
- `StationToggles` gains `Transmit` (default off); `Toggle` gains `Transmit`.
- `EngineStatus` gains `Transmit` (`TransmitStatus`: `On`, `Blocked`, `LastSent`, `ReceiveOnly`); `SourceStatus` gains
  `Transmit` (whether that source can send now, and why not).
- `IEngineService.SendPositionAsync(sourceId)` returns the copies sent (`PacketView`, one per source): on every source
  that can send when `sourceId` is null, on that one otherwise; hub method `SendPosition`.
- `IEngineService.TestSendAsync(sourceId)` returns the result and, within 30 s, where it was heard back; hub method
  `TestSend`.
- `PacketMarkers.Sent`.
- Error codes `transmit.*` (an operation failure), including `transmit.profile-disabled`, `transmit.source-disabled`
  `transmit.no-source` and `transmit.not-licensed`, and `settings.profile.comment-invalid`, `settings.profile.symbol-invalid`,
  `settings.source.tx-path-invalid`.
- `EngineOptions.ReceiveOnly` (the refusal and the status; F1.26 adds the unverified login).

## APRS.NET dependencies

G01 (`PacketAddress`, `PositionReport`, the encoders), G02 (`AprsIsConnection.SendAsync`, which refuses an unverified
login itself) and G13 (`KissConnection.SendAsync` over TCP): delivered. No blocker. KISS over serial moves to 0.6.0 with
F3.1's serial part.

## Acceptance tests

1. Transmit is off in new settings and in settings stored before this feature; so is every source's TX enabled, and
   Disable TX is unticked on every profile.
2. Turning Transmit on is refused with the right code for each failing condition of behavior 6.1, and allowed when all
   hold; off always works; switching profiles turns it off.
3. Send position now, with Transmit on, a verified APRS-IS source and a connected TNC both TX enabled, writes
   `CALL>TOCALL:!DDMM.mmN/DDDMM.mmW-comment` to APRS-IS and `CALL>TOCALL,WIDE1-1,WIDE2-1:…` as a KISS frame to the TNC;
   the packet list shows both marked `Sent` with their sources; the profile is marked `PositionConfirmed`, and changing
   its location clears it.
4. A source without TX enabled is never sent on, by Send position now or Test send; a profile with Disable TX sends
   nothing anywhere, and neither does one saved unlicensed (`transmit.not-licensed`), including through a verified
   APRS-IS login; with the Transmit switch off, Test send is
   refused with `transmit.off`.
5. With Transmit on and every source's connection dropped, sending is refused with `transmit.not-connected` and the
   status says so; with one of two down, the other still sends.
6. A source pill's Send position now sends on that source alone, and isn't in the menu of a source without TX
   enabled. Test send on a TNC sends one status report there and nowhere else; a copy repeated by a digipeater within 30 s is
   reported as heard back through it.
7. On the gateway, Transmit, Send position now and Test send are refused with `gateway.operator-only`, with
   `AllowSettingsChanges` on and off.
8. A comment over 43 characters, or with a non-ASCII character, a symbol that isn't two printable characters, and a TX
   path APRS.NET refuses, are refused on save.
9. A new profile with the licensed box unticked gets a listener ID matching `SWL` and six digits, logs in to APRS-IS
   with passcode -1, and every send is refused with `transmit.not-licensed`; ticking it shows the callsign and Disable
   TX, and unticking it brings the listener ID back.

## Decisions for review

1. **Transmit is a quick toggle** (proposed), saved with the others, so a station that was transmitting keeps
   transmitting after a restart, held by the checks in behavior 8 and by the interlock for automatic sends.
2. **A dropped or unverified login holds sending without turning Transmit off** (proposed), so a short outage doesn't
   need the user; switching profiles does turn it off.
3. **`!` until messaging exists** (proposed): `=` would tell others the station answers messages.
4. **The gateway refuses transmitting outright until F2.9** (proposed), rather than trusting `AllowSettingsChanges`.
5. **The interlock is cleared by a change to what's sent** (proposed): callsign, symbol, comment or location.
6. **Three layers: profile, source, master switch** (decided, 2026-10-17): Disable TX on the profile, TX enabled on each
   source, and the Transmit switch over both.
7. **Test send needs the Transmit switch on** (decided, 2026-10-17), as well as the source's TX enabled and the
   profile's permission: nothing is sent while the master switch is off.
8. **The licence confirmation is on the profile** (decided, 2026-10-17), not on each source: once per profile and
   callsign, covering APRS-IS and RF alike. An unlicensed user's profile is receive only.
10. **Unlicensed users get a generated listener ID** (decided, 2026-10-17): `SWL` and six random digits, so nobody
    types a made-up or borrowed callsign; transmitting anywhere stays for licensed operators.
9. **Send position now goes out on every source that can send** (decided, 2026-10-17), and each TX-enabled source's
   pill menu has its own Send position now for that source alone; beacons and messages pick theirs.
