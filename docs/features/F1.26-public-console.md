# F1.26 Public receive-only console

Status: spec'd for 0.5.0 ([#174](https://github.com/APRS-NET/AprsMap/issues/174)), decisions reviewed 2026-10-18. A
maintainer request (2026-10-16): run the gateway as a standalone, always-on page showing what a TNC hears, safe to
expose publicly, with the station's settings still reachable privately. Revised after F2.9: the operator port is where
an operator signs in, not a role by itself.

## User story

As an operator with a TNC on an always-on computer, I run the gateway container on my home server, listening to the
TNC over KISS TCP, and share a public web page that shows what my TNC hears, from anywhere. Nobody who opens that page
can change the station, transmit, or work out exactly where I live. I change the station's settings myself, privately,
through a second port only I can reach.

## Background: what already exists

- `Gateway__AllowSettingsChanges` (F0.4, F1.14), off by default: browsers can look but not change the station. With it
  off, settings, profiles, sources, toggles and source switches, clear data, reconnect, address lookup and passcode
  computing are refused (`gateway.settings-read-only`, `gateway.operator-only`), and the passcode is blanked out of the
  settings sent to browsers. Settings are read from `/data/settings.json` at start.
- Nothing transmits yet. APRS-IS logs in receive-only without a passcode; KISS sources (F3.1) never send. Transmitting
  is Phase 2 and needs a verified login and, on a gateway, a signed-in operator (F2.9).
- Viewer limits, rate limits, CSP and trusted proxies (F1.14).

This feature makes the safe setup explicit and keeps it safe after Phase 2, separates the public and private ways in,
and adds what a public page needs.

## Behavior

### Two ports: a public one and the one operators sign in on

1. **Viewer port** (the gateway's HTTP port, `8080` in the image): always the **viewer** role. Everything F1.14 shows a
   read-only viewer, nothing that changes the station. It never offers sign-in (F2.9 behavior 8.2): `/auth/sign-in`
   there answers `auth.not-offered-here`, a session cookie brought to it is ignored, and the app menu has no Sign in.
2. **Operator port**, off unless `Gateway__OperatorPort` is set (for example `8081`): where an operator **signs in**
   (F2.9). Reaching it doesn't make anyone the operator: a connection there is a viewer until it signs in, then has
   what F2.9's operator may do.
3. **The port is the server's local port for the request**, checked at `/auth/*`, at the hub's negotiate request and on
   every hub call. Never a header, a path, a query string or anything a browser or proxy sends, so a reverse proxy
   pointing at the viewer port can't offer sign-in there.
4. **Compatibility:** `Gateway__AllowSettingsChanges=true` keeps meaning what F2.9 behavior 17 says: with no operator set
   up, every browser on either port may change settings; once an operator exists it's ignored. With an operator port
   configured, the gateway logs a warning at start if it's on.
5. **Reaching the operator port privately** is still the deployment's job, as a second lock beside the password: publish
   it on the host's loopback only (`127.0.0.1:8081:8081` in Compose) and reach it over an SSH tunnel or a VPN such as
   Tailscale. Sign-in there over plain HTTP is allowed only from loopback (F2.9 behavior 8.1), which an SSH tunnel is.
6. `/healthz` answers on both ports; `/source` (AGPL section 13) on both.

### Receive only, for good

7. **`Engine__ReceiveOnly=true`** makes the station receive only, whatever the settings, the login or the role:
   1. anything that would transmit (Phase 2: beacons, messages, objects, IGate, digipeating) is refused by the engine
      with a new `engine.receive-only` error, from any port;
   2. APRS-IS logs in without a passcode (`-1`, an unverified login the server won't accept packets from), even when the
      profile has one;
   3. KISS sources open read-only, as they are now;
   4. it can only be set where the engine starts (environment or `appsettings.json`), never from a browser or the
      operator port, and it's reported in `EngineStatus.ReceiveOnly`;
   5. the UI shows a quiet **Receive only** badge in the status bar and leaves out every transmit control.
8. Without it, a gateway still never transmits for a viewer: transmitting stays an operator action (F2.9).

### The viewer's page

9. **Nothing that changes the station is shown to a viewer**: no Settings sections for profiles, sources, units or
   data, no Clear data or Clear stations, no switches inside the pills or on the dashboard, no Reconnect now. Today they
   show but are refused or disabled; on the viewer role they're left out. A viewer keeps what's their own and stored in
   their browser: Appearance (theme, text size, map options) and the layout.
10. **A title** for the page, `Gateway__Title` (for example "What NZ0P's TNC hears"), shown in the top bar beside the
    product name and as the browser tab's title, on both roles.

### Location privacy

11. **`Gateway__HomePrivacy`**, for the viewer role only: `exact`, `grid` or `hidden`. Unset, it's **`grid` when an
    operator port is configured** (a public/private split) and **`exact` otherwise**, as today (decision 4).
    1. **grid**: the station's location is replaced, for viewers, by the centre of its 4-character Maidenhead square
       (about 110 × 220 km at mid-latitudes). The house is drawn there, and everything measured from home (distances,
       bearings, the range circles, the "this station" route ends and network links of F3.1 behavior 8, the station's
       own details) is measured from that point, so the exact location can't be worked out from distances to known
       stations.
    2. **hidden**: no house, no distances or bearings from home, no filter circles, and routes and links that end at
       this station stop at the last digipeater.
    3. A signed-in operator always sees the exact location.
    4. Settings sent to a viewer have the profile's location replaced the same way.
12. This doesn't hide a position the station itself sends: once Phase 2 beacons, a beacon is public on APRS-IS anyway.
    The setting covers what the gateway adds.

### Map tiles on a public page

13. The gateway proxies and caches map tiles for its browsers (F1.4), so a public page's viewers share its cache.
    OpenStreetMap's tile servers allow light use only; the deployment guide says that a public page should use a tile
    provider whose terms allow it, with its own key, or a self-hosted tile server, and how to configure one.

### Running without the UI first

14. **A KISS source from the environment**, for a headless first start: when the settings volume is empty,
    `Engine__Kiss__Host` (with optional `Engine__Kiss__Port`, `Engine__Kiss__TncPort` and `Engine__Kiss__Name`) creates a
    KISS over TCP source (F3.1) and ticks it for the first profile, as `Engine__Server` creates the APRS-IS source today.
    With `Engine__Server` left empty, the first profile has no APRS-IS source: a TNC-only station. After the first
    start the stored settings win, as for the other first-run values.

### Deployment guide

15. A section for this setup, with a Compose example on the published image:
    1. `/data` on a volume or a bind mount (owned by the image's `app` user, UID 1654), for example Unraid's
       `/mnt/user/appdata/aprsmap`;
    2. the viewer port published, behind a reverse proxy with TLS (Nginx Proxy Manager, SWAG, Caddy or a Cloudflare
       Tunnel), with `Gateway__KnownProxies` set;
    3. the operator port on `127.0.0.1` only, and how to reach it over SSH (`ssh -L 8081:127.0.0.1:8081 server`) or a
       VPN;
    4. `Engine__ReceiveOnly=true`, `Gateway__HomePrivacy=grid` and a title, as the recommended public settings, with
       the viewer and rate limits to start from;
    5. the TNC on another computer: a Raspberry Pi with the TNC on USB, serving it as KISS over TCP, and the gateway
       connecting to it as a KISS over TCP source, so its packets are heard by this station (F3.1 behavior 8). No USB
       device is passed into the container. On the Pi, `ser2net` bridges the serial port to a TCP port as raw bytes,
       which is KISS over TCP. (APRS.NET's `aprscli serve --tnc serial:…` serves an APRS-IS-style feed instead; the
       gateway could use it as an APRS-IS source, but its packets would then read as from the internet, not heard by
       this station.) Passing a USB TNC into the container instead is covered with KISS over serial (F3.1).

## Service surface

- `EngineStatus` gains `ReceiveOnly`.
- New error code `engine.receive-only`.
- The gateway's hub endpoint decides the role per connection from its local port; the read-only settings it already
  sends a viewer (passcode blanked) also apply `HomePrivacy`. Station states, details, routes and links sent to a viewer
  connection are measured from the private point under `grid`, or carry no home-derived fields under `hidden`; this is
  done at the gateway, so the in-process desktop app is unaffected.
- Gateway options: `OperatorPort`, `HomePrivacy`, `Title`. Engine options: `ReceiveOnly`, and `Kiss` (first-run seed).

## APRS.NET dependencies

- Maidenhead conversion (G08) and KISS over TCP (G13): delivered.
- **Nice to have, not blocking**: an `aprscli` command that serves a serial TNC as KISS over TCP for other apps, with
  APRS.NET's `KissTcpServer` (which shares a TNC with several KISS apps) and `KissSerialConnection` (which reopens it
  after an unplug), so the Pi can run APRS.NET instead of `ser2net`. To be raised in APRS.NET if wanted.

## Desktop vs web differences

| | Desktop | Web (gateway) |
| --- | --- | --- |
| Roles | One user, operator | Viewers; an operator signs in, on the operator port when there is one |
| Receive only | `Engine:ReceiveOnly` in `appsettings.json` | Environment variable |
| Home privacy | Not applied (it's your own screen) | Viewer role |

## Acceptance tests

1. With an operator port configured, sign-in on the viewer port is refused with `auth.not-offered-here` and a session
   cookie brought there is ignored; on the operator port a connection is a viewer until it signs in, then an operator;
   forged `X-Forwarded-*`, `Host` or path values change neither.
2. `AllowSettingsChanges=true` with an operator port logs the warning; with no operator set up it allows changes on
   both ports, and once one exists it's ignored.
3. `ReceiveOnly`: the APRS-IS login carries passcode `-1` although the profile has one; a transmit call is refused with
   `engine.receive-only` on both ports; the status reports it and the badge shows.
4. With an operator port and `HomePrivacy` unset, viewers get `grid`; without an operator port, `exact`.
   `HomePrivacy=grid`: a viewer's house, distances, bearings, route ends and links use the 4-character square's
   centre; the operator sees the exact location; `hidden` sends no home-derived fields and no filter circles.
5. The viewer role's UI leaves out every control that changes the station; Appearance still works.
6. A first start with `Engine__Kiss__Host` and no `Engine__Server` creates a TNC-only profile with that KISS source.
7. Manual, on the test bed: the image on Unraid with `/data` in appdata, the viewer port behind a reverse proxy, the
   operator port over an SSH tunnel, and a Raspberry Pi serving a TNC-X over KISS TCP with `ser2net`.

## Decisions for review

1. **Sign-in offered only on the operator port** (agreed 2026-10-18): the local port decides where a password box
   appears, never who the operator is; that's always the sign-in (F2.9). Nothing a proxy or a browser sends can move
   sign-in to the public port.
2. **Keep `AllowSettingsChanges`** (agreed 2026-10-18) for compatibility and simple LAN setups, warning when it's combined with
   an operator port.
3. **Receive only means an unverified APRS-IS login** (agreed 2026-10-18): receiving doesn't need the passcode, and a server
   won't accept packets from an unverified login, so a mistake elsewhere can't send.
4. **`HomePrivacy` defaults to `grid` with an operator port, `exact` without** (agreed 2026-10-18): a public/private
   split almost always wants the house hidden, and forgetting a setting shouldn't give it away.
5. **The viewer keeps Appearance** (agreed 2026-10-18): it's stored in their browser and changes nothing for anyone else.
6. **A first-run KISS source from the environment** (agreed 2026-10-18), so a headless gateway can start TNC-only without the
   operator port.
