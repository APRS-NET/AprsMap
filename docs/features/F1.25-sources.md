# F1.25 Sources

Status: draft

## User story

As an operator, I tell the app where APRS traffic comes from: APRS-IS, and later a TNC on a serial port, a Direwolf
on my network, or a GPS. I set each one up once and choose, per station profile, which ones it uses. Everything I see
says which source it came from, and a packet heard on several sources shows once, with where else it was seen.

Built already: one APRS-IS connection per profile, with the server, passcode and filter on the profile (F0.4, F0.8,
F1.1).

## Behavior

### The source list

1. **Settings › Sources** is a master list of sources. Each has a name and its connection details:
   - **APRS-IS** (0.3.0): the server, and optional extra filter text added to the automatic filter (F1.2);
   - **KISS over TCP** (0.4.0): host and port (Direwolf, soundmodem: default 8001);
   - **KISS over serial** (0.4.0): port and speed (MFJ TNC-X, NinoTNC, Bluetooth serial);
   - **GPS** (with beaconing, F2.2): NMEA over serial or TCP, or gpsd; see behavior 12.

   Until a kind is built it is listed in **Add a source** as "coming", so the shape of the feature is visible.
2. **Add a source** asks for the kind, then its details, then a name (defaulting to the server or port). A source can
   be edited and deleted; editing one shows **Used by:** the profiles that use it, and deleting one in use asks first.
3. There is **at most one APRS-IS source in use at a time** (one login per station), and any number of the others.
   The list may hold several APRS-IS sources (a regional server and a rotate, say); a profile picks one.

### Profiles pick their sources

4. Each profile (F0.8) has a **Sources** list: ticks against the master list, at most one APRS-IS source. Switching
   profile opens the sources it uses and closes the rest; a source used by both stays open (a TNC isn't reopened).
5. What identifies the station stays on the profile: **callsign, passcode and location**. What says where to connect
   is on the source. One APRS-IS source serves every profile, each logging in with its own callsign and passcode.
6. A new profile starts with the active profile's sources. A profile with no sources is allowed (nothing is received)
   and the status bar says so.
7. **The setup wizard** (F0.5) sets up an APRS-IS source by default, as now: its server step creates the source (or
   picks an existing one with the same server) and ticks it for the profile. A **Use a TNC instead** choice on that
   step comes with the KISS kinds (0.4.0), for a station that receives on RF only.

### Received data

8. Every packet records the **source it arrived on**. The packet list (F1.8) shows it as a column, filterable.
9. A packet heard again on another source within the duplicate window (G05, 30 s) isn't shown or counted twice: the
   first one stands, and its **Seen on** list gains the other source. A station (F1.3, F1.6) keeps **First heard via**
   and **Seen on** for its latest report.
10. With one source, nothing about sources is shown in lists, so the common single-APRS-IS case looks as it does
    today.

### Status

11. The status bar shows one connection pill per open source (the UX doc's "one pill per connection"): APRS-IS as now
    (F1.1), and each TNC with its own state. The pill's menu has Reconnect now for that source. On a gateway, sources
    and their pills are the station's, like every setting (F0.4 operator gate).

### GPS (with beaconing)

12. A GPS source has **Position for**:
    - **My station** (default): while fixes are fresh, the active profile's position is the GPS position (F1.13
      behavior 1); when they stop for longer than a set time, it falls back to the profile's fixed location and the
      status bar says so;
    - **A tracked position**: a named marker on the map that follows the GPS, for a GPS somewhere else (a remote site
      reached over TCP or a virtual serial port). Once transmitting exists it can be beaconed as an object (F2.7).

    A GPS reached over TCP is just a source like the others, so local and remote GPS work the same way.

## Service surface

- `AppSettings` gains `Sources` (the master list). `StationProfile` loses `Server` and `Filter` and gains `SourceIds`;
  `Passcode` and the location stay. Each `SourceSettings` has `Id`, `Name`, `Kind` and the kind's details (`Server`,
  `Filter` for APRS-IS).
- **Migration:** settings without `Sources` are read the old way and converted on load: one APRS-IS source per distinct
  server (filter text kept on the source when profiles sharing a server agree, otherwise one source each), and each
  profile ticks its own. The converted settings are saved once; the old file is kept as `settings.json.v1`.
- `EngineStatus` gains `Sources`: per open source, its id, name, kind and the connection state F1.1 defines (state,
  server, verified, retry time, reconnects, error). The top-level connection fields stay for the APRS-IS source.
- `PacketView` gains `SourceId` and `SeenOn` (other source ids); `Station` gains `FirstHeardVia` and `SeenOn`.
- `IEngineService.ReconnectAsync(sourceId)`; the parameterless form reconnects the APRS-IS source.

## APRS.NET dependencies

- **G05, duplicate detection** (APRS.NET #118): needed for behavior 9. It must report a duplicate and which source it
  came from, not only drop it (gap G29, added to #118).
- **0.4.0, KISS:** **G13** for KISS over TCP (built, published by APRS.NET #98) and a serial connection that survives a
  USB unplug and replug, with port listing (G13, still open); **G12** AX.25 (built, published by #98).
- **GPS:** **G17** NMEA parsing, and **G30**, a gpsd client.

## Desktop vs web differences

| | Desktop | Web |
| --- | --- | --- |
| Where a serial TNC or GPS plugs in | This computer | The gateway's host (a container needs the device passed through) |
| Managing sources | Anyone | Operator only (F0.4 gate) |

## Acceptance tests

1. Old settings with two profiles on different servers migrate to two APRS-IS sources, each ticked by its profile;
   nothing about the connection changes; the old file is kept.
2. Add a source creates an APRS-IS source; a profile can tick at most one APRS-IS source; the other kinds show as
   coming.
3. Editing a source used by two profiles shows both; deleting it asks first and unticks it.
4. The wizard creates the APRS-IS source and ticks it, or reuses an existing one for the same server.
5. With one source, the packet list and station details look as before; with two fake sources, a packet on both shows
   once with Seen on listing the second (after G05).
6. Switching between profiles that share a source keeps it open (the fake source counts opens).
