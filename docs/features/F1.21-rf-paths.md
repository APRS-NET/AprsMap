# F1.21 RF paths

Status: built ([#122](https://github.com/APRS-NET/AprsMap/issues/122)). Show path (behaviors 2, 3): a packet picked
in the list or a point of the selected track, drawn as arrows through digipeaters and a dotted last leg to the IGate,
with the distance on a direct line; the selected station's last packet's route is in words in the details
(`GetRouteAsync`). Network (behaviors 4, 5): RF links of the last hour between stations with known positions, as
dashed lines in the track colour, thicker for more packets, refreshed every 30 seconds and on each selection
(`GetNetworkLinksAsync`): the selected station's links, or every link with **Show all RF connections**. Settings ›
Map › Packet paths: Selected station (the default, decision 4) · Off, and the Show all RF connections checkbox
(decision 5). Local RF only (behavior 7) is what the network already is: links come only from packets heard on RF.
Not built: hovering a link for its ends and count.

## User story

As an operator interested in my local RF network, I can see how packets travel: the digipeaters a station's packet
went through on its way to an IGate, drawn as lines on the map, and over time which digipeaters talk to which, so I
can see the network's shape and its gaps.

## Behavior

### Per-packet paths

1. For a packet heard on RF (G20: the q-construct says an IGate heard it on RF), its **path** is the chain: the
   source's position → each digipeater that inserted its callsign, in order → the IGate. Hops whose station has no
   known position (or that used a generic alias without inserting a callsign) are skipped, and the line joins the
   known points with a dotted segment.
2. **Show path**: selecting a packet in the packet list (F1.8) or a track point (F1.5) draws that packet's path;
   selecting a station draws its links instead (behavior 5), with its last packet's path in the details. It's drawn under symbols and
   labels, from theme tokens, until the selection changes. The details (F1.6) list the hops in words with distances.
   - **Heard directly** (`PathAnalysis.IsHeardDirectly`: no digipeater used): a **dotted line** from the station's
     position in that packet to the IGate that reported it (`EntryStation`), labelled with the IGate's name and the
     distance ("Heard directly by T2IGT, 23 km"). This is the most useful case: it shows how far the station reaches
     on RF with no help.
   - **Digipeated**: arrows from hop to hop, source → each digipeater → IGate, with each hop's name, and the last leg
     to the IGate dotted like a direct one, since the IGate heard that digipeater directly (decision 2).
   - The IGate or a digipeater whose position isn't known (it hasn't sent one): the line stops at the last known point,
     and the details name the rest ("then T2IGT, position unknown").
   - A packet also heard on another source (F1.25 `SeenOn`) draws the path as the first source reported it; the
     details list where else it was seen (decision 3).
3. Packets that came from APRS-IS without RF (q-construct says not RF) have no path to draw, and the details say
   "Not heard on RF".

### Network links

4. The engine aggregates **links** from paths over the last hour: each pair of consecutive known hops (digipeater to
   digipeater, source to first digipeater, last digipeater to IGate) with a count of packets.
5. **Links on the map**: a dashed line between a link's ends, thicker for more packets, in the palette's track colour
   (the dashes tell it from a solid track). Selecting a station draws its links, both ways, and clearing the
   selection hides them: an IGate or digipeater shows the stations it heard, a mobile station the digipeaters and
   IGates that heard it. **Show all RF connections** (a checkbox under Packet paths) draws every link, selected or
   not. Hovering a link shows its ends and count.
6. **Paths layer** (Settings › Map): Selected station · Off, default Selected station, and Show all RF connections,
   default off. Per viewer. An earlier "RF network" choice reads as Selected station with Show all ticked.

### Local RF only

7. **Local RF only** (a view filter condition, F1.9 "Reception: RF"): with links shown, shows only links from
   packets heard on RF. When the station has its own RF port (Phase 3), it gains "heard by me": paths ending at this
   station's own receiver.

## Service surface

- `StationDetail` (F1.6) gains `PathHops`: each hop's callsign, position when known, and whether it was used, plus the
  reporting IGate and whether the packet was heard directly.
- A packet list entry (F1.8) and a track point (F1.5) carry their packet's hops the same way, so selecting one draws
  its own path.
- New `IAsyncEnumerable<LinkBatch> WatchLinksAsync()`: the network links with counts, as a snapshot then changes,
  coalesced like stations (F0.2), only while a viewer shows links.

## APRS.NET dependencies

- **G20, path analysis**: used digipeaters in order, the q-construct and IGate, heard on RF: delivered
  (`0.2.0-alpha.2`, `PathAnalysis`).

## Desktop vs web differences

None.

## Acceptance tests

1. Corpus packets with `WIDE1-1` and inserted digipeater callsigns produce the expected hop chains; generic aliases
   are skipped.
2. Links aggregate over a sliding hour with counts (fake clock); a link's last packet leaving the hour removes it.
3. A selected IGate draws its links to the stations it heard, a selected mobile its links to what heard it, and no
   selection draws none; Show all RF connections draws every link, thicker by count; Off draws nothing.
5. A directly heard packet draws one dotted line to its IGate with the name and distance; a digipeated one draws arrows
   and a dotted last leg; an IGate with no known position draws no line but is named in the details.
6. Selecting a packet in the packet list draws that packet's path, not the station's last one.
4. APRS-IS-only packets show "Not heard on RF".

## Decisions for review

1. **One-hour window for links** (proposed): long enough to show a quiet network, short enough to reflect changes.
2. **Digipeated paths on selection** (proposed: draw them). The maintainer asked whether they're worth it. Proposed yes,
   because they answer "which digipeater got this station out", and the direct case alone would hide most mobile
   stations' paths. Drawing them costs little: the hops come from the same `PathAnalysis`. The alternative is direct
   only, with digipeated paths in words in the details.
3. **Repeated reports** (proposed: first report only). APRS-IS drops duplicates before they reach a client, so the
   other IGates that heard the same packet are never seen; only F1.25's several sources can show more than one. A
   line per extra source would mostly repeat the first, so they're listed in the details instead. Revisit with a
   station's own RF port (Phase 3), where "heard by me" adds a second, local report worth drawing.

4. **Paths default to Selected station** (built that way; behavior 6 proposed Off). The maintainer asked for a click on
   a station or packet to show its path, so it shows without a trip to Settings; Off is one choice away.
5. **Links for the selected station, all of them on request** (maintainer, 2026-10-16): the whole network drawn all the
   time crowded the map, so a selected station shows its own links, and Show all RF connections brings the rest back.
   A selected station's last-packet route is no longer drawn over its links (it repeats their first leg); it stays
   in the details, and a picked packet or track point still draws its route.
