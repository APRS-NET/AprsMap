# F1.14 Gateway

Status: building ([#72](https://github.com/APRS-NET/AprsMap/issues/72))

Built: behind a proxy (path base, trusted forwarded headers), the security headers, and caching with precompressed files
(behaviors 1, 2, 9, 10). The browser app finds its hub under its own address. Still to build: limits, connection and
versions, visibility (behaviors 3–8, 11).

## User story

As someone running a station for a club or a household, I start one container and everyone on the network opens the
map in a browser, with nothing to install. Viewers can look but not change the station. The gateway behaves well
behind a reverse proxy, can't be overwhelmed by a crowd of viewers or a misbehaving client, and tells a browser
clearly when it has lost the connection or is out of date.

Built already: the gateway hosts the engine and serves the browser app (F0.3); the SignalR hub with every
`IEngineService` member (F0.2); read-only settings for browsers with `Gateway:AllowSettingsChanges` (F0.4); `/healthz`;
`/source` (AGPL section 13); the startup page that times out when no gateway answers (F0.5); the Docker image and
deployment guide (F0.3). This feature completes it for use on a real network.

## Behavior

### Behind a proxy

1. **Path base**: `Gateway:PathBase` (for example `/aprs`) serves the app, hub, tiles and health check under that
   prefix, for a proxy that maps a path to the gateway. The browser app finds its hub relative to its own address, so
   it needs no setting.
2. **Forwarded headers**: `Gateway:KnownProxies` (addresses or networks) trusts `X-Forwarded-For` and
   `X-Forwarded-Proto` from those proxies only, so the viewer's address (used for limits) and the scheme are right.
   With none set, forwarded headers are ignored.

### Limits

3. **Viewers**: at most `Gateway:MaxViewers` (default 100) connected browsers, and 5 per address. A browser over the
   limit gets `gateway.busy` and the startup page says the gateway is full and retries every 30 s.
4. **Calls**: each viewer may make at most 20 hub calls a second (bursts of 40); over that, calls fail with
   `gateway.rate-limited` and the viewer's UI backs off. Geocoding keeps its own limit (F0.5).
5. **Message size**: hub messages from browsers are limited to 64 KB (settings are the largest call).
6. **Slow viewers**: a viewer whose streams fall behind (its send buffer full for 30 s) is disconnected rather than
   holding memory for everyone; its browser reconnects and starts from a snapshot.

### Connection and versions

7. **Losing the gateway**: the browser reconnects by itself (already built, with backoff). While it does, the status bar
   says "Reconnecting to the gateway…", and the map and lists stay as they were, marked stale. After reconnecting, the
   streams restart from a snapshot.
8. **Version check**: the hub's handshake compares the contract version of the browser app and the gateway. After a
   gateway upgrade, a browser running the old app is told "A new version is available · Reload" instead of failing
   calls.
9. **Caching**: the app's files are served with content hashes and long cache lifetimes, except `index.html` and the
   boot manifest, which always revalidate, so an upgrade reaches browsers on their next load. Files are served
   compressed (Brotli, gzip).

### Security headers

10. Every page response carries a Content-Security-Policy that allows only the gateway's own origin for scripts,
    WebAssembly (`'wasm-unsafe-eval'`), connections and images, plus `X-Content-Type-Options: nosniff`,
    `Referrer-Policy: same-origin` and `frame-ancestors 'self'` (configurable for embedding).

### Visibility

11. The operator (and any viewer when settings are allowed) sees the number of connected viewers in About and in the
    gateway's metrics (`aprsmap.gateway.viewers`). The engine logs viewer connects and disconnects at Information level
    without addresses, and limit refusals at Warning level with them.

## Service surface

- No new `IEngineService` members. `EngineStatus` gains `Viewers` (int?, null on desktop).
- New error codes: `gateway.busy`, `gateway.rate-limited`, `gateway.outdated`, with UI text.
- `GatewayOptions` gains `PathBase`, `KnownProxies`, `MaxViewers`, `MaxViewersPerAddress`, `FrameAncestors`.
- `EngineHub.ContractVersion`, compared during connection (a query value on the hub URL, checked in `OnConnectedAsync`).

## APRS.NET dependencies

None.

## Desktop vs web differences

Gateway only; the desktop app runs the engine in process.

## Acceptance tests

1. In-memory gateway tests (`WebApplicationFactory`):
   1. under `PathBase=/aprs` the app, hub and health check answer and `/` doesn't;
   2. forwarded headers are honoured from known proxies only;
   3. the 101st viewer and the 6th from one address are refused with `gateway.busy`;
   4. 100 calls in a second are cut to the limit with `gateway.rate-limited`;
   5. an old contract version gets `gateway.outdated`.
2. Headers: CSP and the others are present, and the published browser app runs under them (headless Firefox, live).
3. Caching: hashed files are immutable, `index.html` revalidates.
4. Live: stopping the gateway shows Reconnecting; restarting it restores the streams.
5. Docker: the container runs under `PathBase` behind a proxy (Compose example in the deployment guide).

## Decisions for review

1. **Default limits**: 100 viewers, 5 per address, 20 calls a second (proposed). A club with more sets a higher limit.
2. **Anonymous viewing stays on** by default (proposed); turning it off needs operator sign-in, so it comes with F2.9.
