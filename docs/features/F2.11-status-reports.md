# F2.11 Status reports with saved alternatives

Status: built for 0.6.0 ([#203](https://github.com/APRS-NET/AprsMap/issues/203)); decisions proposed 2026-10-19 for the
maintainer's review. In the UI: Settings › Beacons › Status.

## User story

As an operator, I keep a few status texts I use often ("QRV on 146.52", "Net control tonight", "Mobile, back at 6"),
pick one instead of retyping it, and send it at once or with the status beacon, with my grid square or the time if I
want them.

## Background: what already exists

- The status beacon (F2.2 behavior 3): on or off, a text of up to 62 characters, an interval and Send via.
- APRS.NET writes status reports (G01, delivered) with a zulu day-hour-minute timestamp, or a Maidenhead locator and
  symbol, and converts a position to a locator (`MaidenheadLocator.FromPosition`).
- Observed in APRSIS32 (docs/reference/observation-2026-10-13.md): a status report on/off with an interval, a status
  text, include grid square, timestamp and DX info; status texts kept to choose from. This design is the app's own.

## Behavior

1. **Saved texts**: the status has a list of saved texts, per profile, at most **20** (proposed). Choosing one puts it
   in the status box; **Save this text** adds what's in the box; **Remove** takes the chosen one off. The list is saved
   with Save, like the rest of the section.
2. **What's sent** is the text in the box, as now; a saved text is a shortcut, not a second status.
3. **Add to the status** (proposed): nothing (the default), **the grid square**, or **the time**. APRS101 lets a status
   carry one or the other, not both.
   1. The grid square is the 6-character locator of the profile's location, followed by its symbol (APRS101 chapter
      16). Without a location, nothing is added.
   2. The time is the UTC day, hour and minute when it's sent.
4. **Length**: 62 characters; 55 with the time, 53 with the grid square (APRS101 chapter 16), checked when saving.
5. **Send status now** (proposed): a button sends the status once on every source the status goes on that can send,
   following every F2.1 rule, as Send position now does for the position. It doesn't change the beacon's schedule.
6. DX info (observed) isn't offered (proposed): it needs a DX cluster feed the app doesn't have.

## Service surface

- `StatusBeaconSettings` gains `SavedTexts` (`IReadOnlyList<string>?`) and `Add` (`StatusAddition`: `None`,
  `GridSquare`, `Time`).
- `IEngineService.SendStatusAsync(string? sourceId = null)`: sends the active profile's status now; returns the packets
  sent. Error codes as Send position now, plus `transmit.no-status` when the text is empty.
- Error code: `settings.profile.saved-status-invalid` (more than 20 saved texts, or one that couldn't be sent).

## APRS.NET dependencies

G01 (status reports and Maidenhead locators, delivered).

## Desktop vs web differences

| | Desktop | Web (gateway) |
| --- | --- | --- |
| Saved texts and what's added | The user | The operator (F2.9) |
| Send status now | The user | A signed-in operator only |

## Acceptance tests

1. A status with the grid square goes out as `>FN31PR/- text` (the locator and symbol), one with the time as
   `>092345z text`.
2. A 56-character status with the time, or 54 with the grid square, is refused; 62 without either is fine.
3. Send status now sends once on each source the status goes on, and refuses an empty text.
4. A browser that isn't a signed-in operator can't send the status.
5. In Settings, choosing a saved text fills the box; Save this text adds it once; Remove takes it off; 21 can't be
   saved.

## Decisions for review

All proposed (2026-10-19), built as described so they can be tried:

1. **Saved texts are per profile, up to 20**, kept with the status beacon's settings.
2. **A saved text fills the box**; the box is what's sent.
3. **Grid square or time, or neither**, as one choice.
4. **Send status now** in Settings › Beacons, a new engine call.
5. **No DX info.**
