# F3.13 GPS from a TNC's port

Status: built for 0.7.0 ([#362](https://github.com/APRS-NET/AprsMap/issues/362)). The plan was agreed with the APRS.NET
session (2026-10-22, recorded on [APRS.NET#320](https://github.com/APRS-NET/APRS.NET/issues/320)); the milestone was
chosen by the maintainer. In the UI: Settings › Sources (a radio in its APRS mode), the radio's pill and the GPS panel.

## User story

As an operator with a radio such as the TH-D72A, which sends its GPS position along with the packets it prints, my
station is placed by the radio's GPS without a second cable or a separate GPS source, and a dedicated GPS still wins
when I have one.

## Background: what already exists

- TNC text output over serial (`AprsTextSerial`, F3.2): a radio in its APRS mode prints what it hears as text lines.
- GPS sources (F3.6) and the GPS status (F3.12): one GPS a profile; its fix places the station while fresh (60 s).
- APRS.NET 0.6.0-alpha.4 (#320, PR #321): `KissSerialConnection` in text mode raises `NmeaSentenceReceived` for each
  whole, checksummed sentence and `GpsPresenceChanged` when the GPS comes or goes (10 s by default), and traces the
  sentences, and the damaged ones, as `Nmea` and `DamagedNmea`. A TH-D72A sends no GPS in KISS mode, so only text mode
  carries it.

## Behavior

1. **The radio's GPS** is a choice on a TNC text output source (only that kind), in Settings › Sources:
   **Use it when the radio sends it** (Auto, the default), **Expect it, and warn when none comes** (On), **Ignore it**
   (Off).
2. With Auto or On, each sentence goes to APRS.NET's `NmeaFixTracker`; its fix and sky reach the engine as a GPS
   source's do. A sentence means a GPS is there, not that it has a fix: the TH-D72A's no-fix placeholder (3600.0000N
   13600.0000E, GGA quality 0) never becomes a position.
3. **On** warns on the radio's pill when no sentence has come within the timeout after connecting, or the GPS goes
   quiet: "No GPS sentences from the radio: some radios, such as the TH-D72A, send GPS only in APRS mode, not KISS". It
   clears when sentences come.
4. **Which GPS places the station** (agreed): a fixed priority, not "best fix", so the station doesn't jump between
   receivers: the profile's GPS source, then a radio set to On, then a radio on Auto, each in the profile's source
   order. The first with a fresh fix is used; a lower one stands in only while every higher one has none. With no fresh
   fix anywhere, the status shows the first expected GPS (a GPS source, or a radio on On), or a radio on Auto that has
   said something. Only the GPS in use drives the moving schedule (F2.2) and the filter's range (F3.6 behavior 7.2).
   **One GPS a profile** still holds: a GPS source beside a radio set to On is refused (`settings.profile.two-gps`);
   beside a radio on Auto it's fine, the radio stepping aside.
5. The radio's pill shows the fix when its GPS is the one in use ("TH-D72A · 3D fix · 7 satellites · RX only"), and the
   GPS panel says which GPS it shows ("From TH-D72A").
6. The Source console shows the radio's sentences as GPS lines, and damaged ones (cut off, wrong checksum) as "GPS
   (damaged)"; damaged ones are never used.

## Service surface

- `SourceSettings.TncGps` (`TncGps`: `Auto`, `On`, `Off`; null for Auto) and `EffectiveTncGps` (Off for every kind but
  TNC text output).
- `EngineErrorCodes.TncGpsMissing` (`source.tnc-gps-missing`); `TrafficKind.DamagedGpsSentence`.
- `EngineOptions.TncGpsTimeout` (10 s).

## APRS.NET dependencies

APRS.NET#320 (the text-mode TNC GPS API), delivered in 0.6.0-alpha.4.

## Desktop vs web differences

None: the engine reads the radio; on a gateway the radio is on the gateway's host.

## Acceptance tests

1. Over a pseudo-terminal, a radio's sentences between its packet lines give a 3D fix from the radio, and packets still
   come.
2. The TH-D72A's no-fix sentences give no position.
3. Off ignores the radio's GPS.
4. On warns when no sentences come, and stops when they do.
5. A GPS source wins over the radio; once its fix is stale, the radio stands in; a GPS source beside a radio on On is
   refused, beside Auto or Off it isn't.
6. Settings offer the choice for text output only and save it (Auto unwritten); the pill and the GPS panel say the
   radio's fix and name.

## Decisions

Agreed with the APRS.NET session and the maintainer (2026-10-22):

1. **Text mode only**: KISS carries no GPS on the radios that matter (TH-D72A).
2. **Auto by default**, On to expect it, Off to ignore it.
3. **Fixed priority**, GPS source first, not best fix.
4. **A GPS source and a radio on On are two GPSs**; Auto steps aside.

Proposed while building (2026-10-25):

5. **The radio's pill isn't warned about** without a fix: it's a working radio; only On's missing GPS warns.
