# F1.15 Quick toggles

Status: draft

## User story

As an operator, I can turn the station's main activities on and off from one place without opening Settings: stop
using the internet when I'm on a metered link, pause APRS-IS, silence sounds at night, and later stop beaconing or GPS.
I can always see which are off, so I never wonder why the map has stopped updating.

## Behavior

### The toggles

1. A **toggles menu**, opened from the status bar's connection area (and `Ctrl+T`), lists switches with their state:
   1. **Internet**: the master switch. Off stops everything that uses the internet: APRS-IS, tile downloads, address
      lookup. Cached tiles still show. It is for metered or emergency links.
   2. **APRS-IS**: connect or not (F1.1). Off disconnects; on connects with the active profile.
   3. **Map tiles**: download new tiles or not; cached tiles still show. On a gateway this is the gateway's
      downloading.
   4. **Sound**: alert sounds on or off (sounds come with messaging and alerts, F2.4).
   5. **Beaconing** (F2.2), **GPS** (F3.6) and **RF ports** (F3.1) appear when those features exist.
2. A toggle that is off and a dependency of another shows it: with Internet off, APRS-IS and Map tiles are shown off and
   disabled with "Internet is off".
3. **State is the station's**: toggles are saved with the settings (`AppSettings.Toggles`) and survive a restart.
   Starting with APRS-IS off is how an operator brings a station up quietly.

### Seeing them

4. Any toggle that is off shows a small marker in the status bar (an icon with a name and tooltip, never colour
   alone), for example "Internet off". Clicking it opens the menu.
5. Toggling announces the new state to screen readers.

### On a gateway

6. Toggles change the station for everyone, so on a gateway they are operator-only (the settings gate, F0.4). Viewers
   see their state and the status bar markers, read-only.
7. **Sound** is the exception: it is per viewer (a browser's own preference), since sound plays where the viewer is.

## Service surface

- `AppSettings` gains `Toggles` (`Internet`, `AprsIs`, `Tiles`, plus later ones), saved with `SaveSettingsAsync` and
  reflected in `EngineStatus` for the markers. A dedicated `SetToggleAsync(name, on)` avoids round-tripping the whole
  settings for one switch, with the same gate.
- `Engine:Enabled` (the current configuration switch) becomes the first-run default of the APRS-IS toggle.
- The tile source (F1.4) and the geocoder (F0.5) check the Internet and Tiles toggles before any request.

## APRS.NET dependencies

None.

## Desktop vs web differences

| | Desktop | Web |
| --- | --- | --- |
| Station toggles | Anyone | Operator only; read-only markers for viewers |
| Sound | Station setting | Per viewer |

## Acceptance tests

1. Internet off: no APRS-IS connection, no tile requests (fake HTTP handler counts), no lookups; cached tiles show.
2. APRS-IS off disconnects; on reconnects; the state survives a restart.
3. Markers show for each toggle that is off, with accessible names, in every palette and at 200 % text.
4. On a read-only gateway, toggles are shown but not changeable; `SetToggleAsync` is refused with
   `gateway.operator-only`.

## Decisions for review

1. **An Internet master switch** that also stops tiles and lookups (proposed), not just APRS-IS.
2. **Toggles saved with the station's settings** (proposed), so a restart keeps a quiet station quiet.
