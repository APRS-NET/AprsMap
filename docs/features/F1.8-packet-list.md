# F1.8 Packet list

Status: built ([#70](https://github.com/APRS-NET/AprsMap/issues/70))

Built: the service surface (the packet's header, kind, symbol, parse issues and third-party marker; the filtered
stream; 5,000 held packets) and the text for every parse issue. Then the Packets panel: rows with time, symbol,
markers, source and summary, expanded to the raw text with the part at fault marked and each issue in words; the raw
text column; pause (button, Space, scrolling down) with the count of new packets; the text, station, type and issues
filters; a row selects its station on the map; Copy and Save; the direct, digipeated (with the hop count) and
duplicate markers, a duplicate's text muted (behaviors 1–3, 5–10). Save writes the rows shown, so
"all" means clearing the filters first, as a text log, CSV, JSON (compact or indented) or YAML. Decided with the milestone: 5,000 packets and
filtering in the engine (decisions 1 and 2, as proposed). Acceptance test 5 was checked by hand with a full feed when #70 closed.

## User story

As an operator, I can watch the raw packets as they arrive, to see what's on the air, check how a station's packets
are reaching me, and find out why a station isn't on the map. I can pause the list to read it, narrow it to one
station or one kind of packet, and see clearly when a packet is malformed and what is wrong with it.

Built already (F0.2): a live list of recent packets (time, source, type, summary) from `WatchPacketsAsync`. It
becomes the Packets panel in the F1.0 shell, docked under the map by default.

## Behavior

### Rows

1. Each row shows the time received, the station's symbol, the source, the packet type, the one-line summary and, on
   request (a column toggle, or a row's expansion), the raw text. The newest is at the top.
2. **Markers** before the source, each with an accessible name and a tooltip, from the packet's path (G20):
   - **Direct**: heard on RF by the IGate that sent it to APRS-IS, with no digipeater;
   - **Digipeated**: with the number of digipeaters used;
   - **Third-party**: carried inside another station's packet (G06);
   - **Duplicate**: seen before within 30 s (G05), shown with the list's muted style.
   Until the gaps ship, the markers aren't shown.
3. **Parse issues**: a packet that APRS.NET couldn't fully decode (`AprsPacket.Issues`) has a warning marker, and its
   expanded row lists each issue in words (for example "The latitude isn't valid", "The object name is too long"),
   translated (F0.9; one string per `ParseIssueCode`, with a guard test that every code has one). The raw text
   highlights the part at fault when the issue gives a position.
4. **Anomalies** (F1.20: duplicate position, impossible speed, sub-second repeats) appear as markers once F1.20 is
   built.
5. Colours come from theme tokens only: markers use the palette's warning and accent colours with a shape or letter,
   never colour alone (F0.6).

### Reading the list

6. **Pause**: a button (and Space with the list focused) freezes the list; new packets are counted in the button
   ("Paused · 42 new") and appear on resume. Scrolling down from the top pauses it automatically; returning to the top
   resumes. Resuming, however it's done, scrolls back to the top, where the newest packets are (maintainer request,
   2026-10-16).
7. **Filter** (above the list, combinable):
   - **Text**: matches source, destination, path or raw text, case-insensitive;
   - **Station**: only one station's packets (set from a row's menu, the details pane, or by typing a callsign);
   - **Type**: positions, Mic-E, objects and items, messages, status, weather, telemetry, other;
   - **Issues only**: packets with parse issues.
   The filters apply to the held history too, so filtering after the fact works.
8. **Clicking a row** selects its station on the map and opens the details (F1.6). **Copy** copies the raw text of the
   selected rows.
9. The list holds the engine's recent packets (`RecentPacketCapacity`, 1,000 now; raised to 5,000) and stays smooth
   with a full APRS-IS feed: rows are virtualized, and incoming packets are added in batches about every 250 ms.

### Logging

10. **Save** writes the held packets (filtered or all), oldest first, to a place the viewer picks (desktop: a save
    dialog; web: a download). Its button opens a menu of formats (maintainer request, 2026-10-16), each written by its
    own exporter:
    1. **Text log (.txt)**: a line a packet, the time received in UTC then the raw text (the original format);
    2. **CSV (.csv)**: a header row and a row a packet (RFC 4180, CRLF), lists joined with "; ". A text value starting
       with `=`, `+`, `-`, `@`, a tab or a carriage return gets a leading apostrophe, so a comment sent over the air
       can't run as a spreadsheet formula;
    3. **JSON (.json)** and **JSON, indented (.json)**: an array of packet objects, every field on every packet (null
       when absent);
    4. **YAML (.yaml)**: a sequence of packet mappings, every string double-quoted and escaped.

    The structured formats carry the same fields, in this order: `time` (UTC, to the millisecond), `source`,
    `destination`, `path`, `type`, `kind`, `summary`, `latitude`, `longitude`, `symbol`, `symbolName`, `hops`,
    `markers` (`thirdParty`, `direct`, `digipeated`), `heardOn` and `seenOn` (source names, F1.25), `issues` (code and
    message) and `raw`.

## Service surface

- `PacketView` gains `Kind` (the type filter's kinds), `Destination`, `Path`, `Issues` (a list of `EngineError`, codes
  `aprs.parse.<kebab>` with the issue's `offset` in the raw text and its `severity`), `Markers` (third-party,
  direct, digipeated and duplicate, with `Hops` for the digipeated count; direct and digipeated come from the outer
  path, how the packet reached APRS-IS), and `Symbol` and `SymbolName` for every packet with a
  symbol. A third-party packet is shown as the packet inside, with the raw text as received.
- `WatchPacketsAsync(PacketFilter? filter)`: the engine applies the filter (text, station, kinds, issues only;
  `PacketFilter.Matches`), so a browser doesn't receive packets it hides. Changing the filter restarts the stream,
  history first.
- Engine option `RecentPacketCapacity` defaults to 5,000.

## Acceptance tests

1. Corpus packets show source, type, summary and symbol; raw text on expansion.
2. Every `ParseIssueCode` has text in every language (guard test); a malformed corpus line shows its issues.
3. Pause holds the list and counts new packets; resume adds them; scrolling down pauses.
4. Each filter narrows the list and the held history; a filtered stream over the gateway sends only matching packets.
5. 5,000 held packets and a full feed: the list scrolls smoothly (benchmark by hand); batches arrive about every
   250 ms.
6. Markers have accessible names and aren't distinguished by colour alone in every palette.
7. Save in each format: text lines with UTC times; CSV with a header, quoting and formula-safe text; JSON that parses
   with every field on every packet; YAML whose strings are quoted so commas, colons, quotes and line breaks in a
   comment keep the document's structure; each file named with its extension.

## Decisions for review

1. **History size**: 5,000 packets (proposed), about 2–3 minutes of a full feed or hours of a filtered one.
2. **Filtering in the engine** (proposed) rather than in the UI, so browsers receive only what they show.
