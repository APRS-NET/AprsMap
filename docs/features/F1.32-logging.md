# F1.32 Logging and telemetry settings

Status: spec'd for 0.6.0 ([#310](https://github.com/APRS-NET/AprsMap/issues/310)), decisions agreed 2026-10-19 (maintainer request). Not built.

## User story

As a user chasing a problem, I turn up the log for just the part that misbehaves, find the day's log file where I
expect it, and send it, without editing a file or knowing how the app was started; logs clean themselves up. As an
operator who watches my station from Grafana or Seq, I send its logs, metrics and traces to one or more OpenTelemetry
endpoints from Settings, with my API keys kept out of sight.

## Background: what already exists

- The log level is set only in `appsettings.json` (`Logging:LogLevel`, Information), and the desktop app logs only to
  the terminal it was started from.
- OpenTelemetry export (`AprsMap.Hosting`) is on when `OTEL_EXPORTER_OTLP_ENDPOINT` is set: logs, metrics (the
  engine's and APRS.NET's meters, runtime, HTTP) and traces all go to that one endpoint; otherwise nothing is sent.
- F1.31 lists the Logs folder in Help › About; this spec defines the log file it points to.
- Found in use (2026-10-19): at Information, the log is nearly all `System.Net.Http.HttpClient.AprsMap.Tiles` lines, one
  for each map tile.

## Behavior

### Settings › Logging

1. A **Logging** section in Settings (maintainer, 2026-10-19), saved with the app's settings (`AppSettings.Logging`),
   for the desktop user and, on a gateway, the signed-in operator only (F2.9). `appsettings.json` and the environment
   give its starting values, and **an environment variable always wins** (`Logging__…`, `OTEL_*`): a setting it overrides
   shows "set by the environment" and can't be changed there.
2. The level, the areas, the privacy switches and the log file apply **at once**; OTLP targets apply **after a restart**
   (the exporters are made when the app starts), and the section says "Restart to apply" after such a change.

### What to log

3. **Overall level**: Errors, Warnings, Information (default), Debug or Trace.
4. **A level per area**, each "Same as overall" by default or its own level (maintainer, 2026-10-19):
   1. **Connections**: APRS-IS, KISS TNCs, serial ports and TNC setup.
   2. **Packets**: parsing, duplicates and what's unexpected (F1.27).
   3. **Messages and bulletins** (F2.4, F2.5).
   4. **Transmit and beacons** (F2.1, F2.2).
   5. **Map tiles**: **Warnings by default** (maintainer, 2026-10-19), so tile downloads don't fill the log.
   6. **Updates and the device list** (F4.15, F4.16).
   7. **Web and sign-in**, on a gateway (F2.9, F1.26).
   8. **APRS.NET**: the library's own log (`AprsNet.*`).
   Each area is a set of logging categories, so a new part of the app joins one; anything not in an area follows the
   overall level.
5. **Two privacy switches**, off by default:
   1. **Log every packet**: each packet received or sent, as its raw text, at Debug in Packets. Off, packets appear
      only when something is wrong with them.
   2. **Log message texts**: the text of messages and bulletins. Off, a message is logged by who, when and its state,
      never what it says.
6. **Never logged**, whatever the settings: passcodes, operator passwords, session cookies, OTLP headers.

### The log file

7. **Write a log file**: on by default on the desktop, **off by default on a gateway**, whose log is the container's
   output (maintainer, 2026-10-19).
8. **Where**: a `logs` folder in the Data folder (F4.15 behavior 13), or on a gateway in `/data/logs`; on the desktop,
   **Choose folder…** picks another and **Reset** returns to the default. A folder that can't be written says why, and
   the app keeps logging to the terminal.
9. **A file per day**, named from the product's slug and the date in UTC: `aprsmap-2026-10-19.log`. Past the **maximum
   file size** (default **10 MB**, 1 to 100), the day goes on in `aprsmap-2026-10-19.1.log`, `.2.log` and so on.
10. **Kept for** a number of days (default **14**, 1 to 365): older files are deleted when the app starts and at midnight
    UTC.
11. **A total cap** (default **100 MB**, 10 to 10,000): when the files together pass it, the oldest are deleted first,
    so a Debug or packet-logging session can't fill a disk before the days run out.
12. Each line has the UTC time, the level, the category and the message, then the exception and its stack when there is
    one. Only this app's files (`aprsmap-*.log`) are ever deleted from the folder.

### OTLP targets

13. **Targets**, a list (maintainer, 2026-10-19), each with:
    1. a **name**, and an **on** switch;
    2. an **endpoint** URL;
    3. a **protocol**: gRPC or HTTP/protobuf;
    4. **signals**: logs, metrics and traces, each ticked or not;
    5. **headers**, such as an API key: once saved, a value shows as "••••" with **Replace**, and is never sent back to
       the UI, so a gateway operator's browser never receives it (maintainer, 2026-10-19).
14. `OTEL_EXPORTER_OTLP_ENDPOINT` (with the other `OTEL_*` variables) still adds a target, listed first as "Set by the
    environment" and read only.
15. **What leaves the station**: the section says that a target receives the station's logs, which name callsigns and
    positions, and that log levels and the privacy switches (behavior 5) apply to them as to the file.
16. A target that can't be reached doesn't stop the app or the others; the section shows its last error.

## Service surface

- `LoggingSettings(LogLevel Level = Information, IReadOnlyDictionary<LogArea, LogLevel?>? Areas = null, bool Packets =
  false, bool MessageTexts = false, LogFileSettings? File = null, IReadOnlyList<OtlpTarget>? Targets = null)` in
  `AppSettings` (`Logging`). `LogArea`: `Connections`, `Packets`, `Messages`, `Transmit`, `Tiles`, `Updates`, `Web`,
  `AprsNet`.
- `LogFileSettings(bool? On = null, string? Folder = null, int MaxFileMegabytes = 10, int KeepDays = 14, int
  TotalMegabytes = 100)`; null `On` means the default of behavior 7.
- `OtlpTarget(string Id, string Name, bool On, Uri Endpoint, OtlpProtocol Protocol, OtlpSignals Signals,
  IReadOnlyList<OtlpHeader> Headers)`; `OtlpHeader(string Name, string? Value)`: the engine returns `Value` null with a
  `HasValue` flag, and a save with `Value` null keeps the stored one.
- `GetLoggingAsync()` and `SaveLoggingAsync(LoggingSettings)`: operator-only on a gateway; `LoggingStatus` with what the
  environment overrides, whether a restart is pending, and each target's last error.
- Error codes: `settings.logging.folder-not-writable`, `settings.logging.limit-invalid`,
  `settings.logging.target-invalid`.
- The file is written by **Serilog's file sink** (`Serilog.Sinks.File`, Apache-2.0) plugged in as one more
  `ILoggerProvider` (`Serilog.Extensions.Logging`), in `AprsMap.Hosting`, the host wiring: Microsoft's logging keeps
  the filters, so the console, the file and OTLP all get the same lines (maintainer, 2026-10-19). Serilog rolls by local
  time, so the host starts each UTC day's file itself, rebuilding the sink with the dated name at midnight UTC
  (`TimeProvider`), as it does after a settings change; Serilog rolls by size within the day (`rollOnFileSizeLimit`).
  Deleting files older than Keep for, and the oldest past the total cap, is the host's small cleanup, run at start and
  at each new day, on `aprsmap-*.log` only. The areas are applied as `LoggerFilterOptions` rules through
  `IOptionsMonitor`, so a level change needs no restart.
- The file and OTLP sit side by side behind `ILogger`, not one behind the other: the .NET OpenTelemetry SDK exports
  over the network only, so a log file without a collector needs its own provider.
  `AprsMap.Hosting` builds the OTLP exporters from the targets and the environment, one named exporter per target and
  signal. Packet and message-text logging check the two switches where they log.

## APRS.NET dependencies

None: APRS.NET logs through `ILogger` and its meters and activity sources are already exported (`AprsNet.*`).

## Desktop vs web differences

| | Desktop | Web (gateway) |
| --- | --- | --- |
| Who changes it | The user | The signed-in operator |
| Log file | On, Data/logs, folder can be chosen | Off; `/data/logs` when on |
| OTLP headers | Saved, masked | Saved, masked, never sent to the browser; a secrets file or `OTEL_EXPORTER_OTLP_HEADERS` recommended |

## Acceptance tests

1. New settings: Information overall, Map tiles at Warnings, both privacy switches off; a tile download writes nothing
   at Information.
2. Setting Connections to Debug logs a KISS connection's details at once, with everything else unchanged.
3. With Log message texts off, a received message is logged by sender and state without its text; on, with it. With
   Log every packet on, each packet's raw text is logged at Debug.
4. A passcode, a password, a session cookie and an OTLP header value never appear in the file, the terminal or a fake
   OTLP target's logs.
5. The file rolls to `.1.log` past its size, starts a new file at midnight UTC (fake clock), deletes files older than
   Keep for, and the oldest first past the total cap; files that aren't the app's are left alone.
6. Off on a gateway by default; on, it writes to `/data/logs`.
7. Two OTLP targets, one with logs only and one with metrics only, each receive only theirs (fake collectors); a header
   saved is masked and absent from `GetLoggingAsync`; a target that can't be reached doesn't affect the other.
8. With `OTEL_EXPORTER_OTLP_ENDPOINT` set, its target is listed read only; with `Logging__LogLevel__Default` set, the
   overall level shows "set by the environment".
9. On a gateway, a viewer's `GetLoggingAsync` and `SaveLoggingAsync` are refused with `gateway.operator-only`.

## Decisions

Agreed with the maintainer (2026-10-19):

1. **Settings › Logging**, with config and environment as the starting values and the environment winning.
2. **An overall level, a level per area, and two privacy switches** (every packet, message texts), off by default.
3. **The log file on by default on the desktop, in Data/logs, folder can be chosen; off by default on a gateway.**
4. **A file per day, a maximum file size, kept for a number of days, and a total cap.**
5. **A list of OTLP targets**, each with its endpoint, protocol, signals, headers and switch; the environment's target
   still added, read only.
6. **Headers saved with the settings and write-only in the UI**, never sent back to a browser.

7. **Map tiles at Warnings by default**: at Information, each tile is four lines, and they were most of the log in use.
8. **Serilog's file sink as a plain provider**, not our own logger: mature file writing (buffering, sharing, flushing
   on exit, a full disk) from a widely used package, while Microsoft's logging keeps the filters; the UTC day and the
   retention are the host's few lines around it.
9. **Defaults: 10 MB a file, 14 days, 100 MB in all**: two weeks of history, files small enough to attach to an issue.
10. **Dates in file names are UTC**, as the lines are, so a file is one UTC day wherever the station is, and daylight
    saving never splits or repeats one.
