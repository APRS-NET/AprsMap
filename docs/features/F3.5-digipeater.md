# F3.5 Digipeater

Status: built for 0.7.0 ([#209](https://github.com/APRS-NET/AprsMap/issues/209)); decisions proposed 2026-10-26 for the
maintainer's review.

## User story

As an operator with a TNC, I can let my station repeat what it hears: as a fill-in digipeater (`WIDE1-1`) for mobiles
in a gap under the wide-area digipeaters, or, by agreement with the local network, as a wide-area one (`WIDEn-N`). I
see what it repeated, and it never repeats unless I've switched transmitting on.

## Background: what already exists

- KISS TNCs over TCP and serial (F3.1) as sources, receiving and sending, with each source's transmit blocks and the
  Transmit switch (F2.1).
- APRS.NET 0.7.0-alpha.1 (G15, APRS.NET#209/#210): `AprsNet.Ax25.Digipeater` decides for each frame heard whether to
  repeat it and with what path, by the APRS 1.1 rules: its own call and aliases, `WIDE1-1` as a fill-in, `WIDEn-N` up to
  a hop limit (trapping longer ones), preemptive digipeating as an option, and a duplicate window. It says why it
  refuses (not APRS, no hops left, not for it, its own frame, a duplicate). `KissConnection.SendFrameAsync` sends a frame
  with its path as is.

## Behavior

1. **Each KISS source has a Digipeat setting** (TCP and serial, not APRS text): **Off** (the default), **Fill-in**
   (`WIDE1-1`, the station's call and its aliases) or **Wide-area** (`WIDEn-N` as well, up to 2 hops, longer requests
   trapped). Aliases, a few names the digipeater also answers to, can be typed beside it (proposed). In Settings ›
   Sources, with a note that wide-area digipeating needs the local network's agreement.
2. **It repeats on the port it heard on**, with the active profile's callsign (its SSID included) as the digipeater's
   call, marked used in the path as APRS 1.1 asks. Only frames heard on RF by that source are considered; nothing from
   APRS-IS is digipeated (that's the two-way IGate's job, F3.4).
3. **Only while the station may transmit there**: the same gate as everything the station sends on that source (F2.1):
   the Transmit switch on, a licensed profile with a verified passcode, the source in the profile and not receive-only.
   With any of those off, nothing is repeated and the setting says why. On the gateway, only the operator changes it
   (F2.9).
4. **The rules are APRS.NET's**: the station's own frames aren't repeated, nor a frame already repeated within 30
   seconds (heard again from another digipeater), nor one with no hops left; a `WIDEn-N` asking for more than 2 hops is
   repeated once and no further. Others' packets are repeated as they are, emergencies included: a digipeater relays,
   it doesn't judge (decision 3).
5. **What was repeated shows**: the packet list marks a packet the station digipeated (**Digipeated here**), the
   dashboard's Connection tile gives each source's count since the app started, and the source's console shows the
   frame sent (F1.28). A metric, `aprsmap.digipeated`, counts them for OTLP.
6. **Profiles change it with them**: the setting is the source's, and the call is the active profile's; switching
   profile changes the call at once.

## Service surface

- `SourceSettings.Digipeat` (`DigipeatMode?`: Off, FillIn, Wide; null is Off) and `SourceSettings.DigipeatAliases`
  (text, names separated by spaces or commas); `EffectiveDigipeat` is Off for a source that isn't a KISS TNC.
- `PacketMarkers.DigipeatedHere`.
- `SourceStatus.Digipeated`: frames repeated on the source since the engine started.
- Error code `settings.source.digipeat-alias-invalid` for an alias that can't be an AX.25 call.

## APRS.NET dependencies

G15, delivered in 0.7.0-alpha.1 (`Digipeater`, `DigipeaterOptions`, `DigipeatDecision`, `KissConnection.SendFrameAsync`).

## Desktop vs web differences

None in behavior. On the gateway the setting is the operator's, like the rest of a source's settings.

## Acceptance tests

Every test that transmits uses a fake TNC or a local Dire Wolf with null audio, never a radio.

1. Fill-in: a frame heard via `WIDE1-1` is sent back to the TNC with the station's call marked used; one via `WIDE2-2`
   isn't.
2. Wide-area: `WIDE2-2` is repeated as `N0CALL*,WIDE2-1`; `WIDE3-3` is repeated once and trapped.
3. Nothing is repeated with Transmit off, from an unlicensed profile or on a receive-only source; the station's own
   frame and a duplicate within 30 seconds aren't repeated.
4. The repeated packet is marked Digipeated here, and the source's count goes up.
5. A bad alias is refused with its error code.

## Decisions for review

1. **Off by default, per source** (proposed): a digipeater transmits on its own, so it's a deliberate choice for each
   TNC.
2. **Two levels, Fill-in and Wide-area** (proposed), with the hop limit at APRS.NET's default of 2 and preemptive
   digipeating left out, as APRS 1.1 advises for generic paths.
3. **Emergencies are repeated like any packet** (proposed). The rule that the app never sends an emergency is about the
   station's own beacons; refusing to relay someone else's emergency would be the opposite of what a digipeater is for.
4. **The count is since the app started** (proposed), in the Connection tile; a dashboard tile over the range can follow.
