# F1.29 Menus and commands

Status: built for 0.5.0 ([#278](https://github.com/APRS-NET/AprsMap/issues/278)), decisions agreed 2026-10-18 (maintainer request). Every command gets one home in a menu, and Settings keeps
only settings. The menu bar is hidden until Alt is pressed on Windows and Linux, is the system menu bar on macOS, and
sits under the ☰ button in the web app.

## User story

As a user, I find any command in one predictable place, the menus, with its shortcut beside it, instead of hunting
through the ☰ menu, the pills, right-click menus and Settings. I show and hide panels from one list and put them back
when I've lost one. The window stays as clean as it is now: the menu bar is there when I press Alt and gone when I'm
done. On a Mac it's in the menu bar at the top of the screen, where Mac menus are.

## Background: what already exists

- **The ☰ app menu** (F1.0): Show for each closed panel, Reset layout, the saved layouts and Save layout as (F1.23),
  Clear data (F1.19), Gather windows, and Sign in or Sign out on a gateway (F2.9).
- **The gear** opens Settings: Profiles, Sources, Beacons, Appearance, Map, Layout, Units, Data (clear data, capture,
  Start over) and About.
- **The pills**: the APRS-IS pill's menu (Reconnect, Console…, Captured packets, the Internet, APRS-IS, Map tiles and
  Transmit switches, Send position now, Send position on APRS-IS). Each other source's pill has Reconnect, Console…, TNC
  commands… and Send position here.
- **Right-click menus**: the map (Set destination here, Set my location here); the station list (Centre, Follow); the
  packet list (Copy).
- **Shortcuts**: Ctrl+, (Cmd+, on macOS) opens Settings; Ctrl+F finds a station on the map; Ctrl+Tab switches panels;
  Enter, L and Ctrl+C in the lists.

None of this goes away: the pills and right-click menus stay as quick ways to the commands most used where they are.
They and the menus run the same commands.

## Behavior

### The menus

1. Five menus, each with access keys (the underlined letter) and the shortcut beside every command that has one:
   1. **File**: Profile ▸ (each profile, the active one ticked; Edit profiles…), Save packet list…, Export captured
      packets…, Settings… (Ctrl+,), Sign in… or Signed in as NAME and Sign out (on a gateway with an operator, F2.9),
      Quit (desktop, Ctrl+Q; in the macOS app menu there).
   2. **View**: Panels ▸ (every panel, ticked while shown: Map, Dashboard, Stations, Details, Packets, Messages,
      Bulletins, Console, Captured packets), Show all panels, Reset layout; Layouts ▸ (each saved layout, Save layout
      as…, Manage layouts…); Gather windows (desktop); Full screen (F11); Always show the menu bar (desktop, behavior 7).
   3. **Station**: the switches, ticked while on (Internet, APRS-IS, Map tiles, Transmit); Reconnect all; Send position
      now, and Send position on ▸ each source; Destination ▸ (Set…, Clear); Sources…, Beacons… (open those Settings
      sections); Console ▸ each source; TNC commands ▸ each serial TNC.
   4. **Tools**: Find a station… (Ctrl+F); Messages; Bulletins; Clear data…; Run the setup wizard again…; Start over….
   5. **Help**: Keyboard shortcuts; Documentation (opens the docs in the browser); Report a problem (opens a new GitHub
      issue in the browser, nothing uploaded); Source code; About (in the macOS app menu there).
2. **A command that can't run now is shown greyed out, not hidden**, with the reason as its tooltip: Transmit with no
   licensed profile, Send position with Transmit off, Clear data for a gateway viewer. A command that can never apply
   here is left out, such as Gather windows in the browser or TNC commands with no serial TNC.
3. **One list of commands feeds every menu**: the menu bar, the macOS menu bar, the ☰ menu, the pills and the
   right-click menus, so names, shortcuts and greyed states never disagree.

### Showing the menus

4. **Windows and Linux desktop**: the menu bar is **hidden by default** (decision 2).
   1. Pressing and releasing **Alt**, or **F10**, shows it with the first menu selected; **Alt + a menu's letter** opens
      that menu straight away.
   2. It hides again when a command is chosen, on Esc, or on a click outside it.
   3. While shown it takes a line above the top bar; the window's content moves down and back without a jump in the
      map's view.
5. **macOS desktop**: the menus are in the **system menu bar** at the top of the screen, with the app menu holding About,
   Settings… (Cmd+,), Hide and Quit (Cmd+Q) as Mac apps do (decision 3). Nothing is drawn in the window.
6. **The web app**: the menus are **submenus of the ☰ button** (decision 4), so Alt stays the browser's. The same
   structure as the desktop, less what doesn't apply in a browser (Quit, Gather windows, Full screen when the browser
   doesn't allow it).
7. **Always show the menu bar** (View menu; Settings › Appearance) keeps the bar shown on Windows and Linux, and in the
   web app shows it above the top bar on wide screens. It's the viewer's own preference, kept with Appearance. Off by
   default.
8. **The ☰ button stays everywhere** (decision 5): it holds the same menus as submenus, for a mouse or touch user who
   doesn't know about Alt, and for the narrow layout.

### Settings keep settings

9. **Actions leave Settings** for the menus (decision 6): Clear data… and Start over… (Tools); Save layout as… and the
   saved layouts list (View › Layouts, with Manage layouts… opening their settings); Export captured packets (File);
   About (Help). Settings keeps the choices: Profiles, Sources, Beacons, Appearance, Map, Layout (the monitor prompt's
   options), Units and Data (capture on or off, its limits).
10. **About** becomes a small dialog from Help › About: the version, the engine's and APRS.NET's versions, the
    connection, viewers on a gateway, failed sign-ins for a signed-in operator (F2.9), the licence, Source code and the
    credits, as Settings › About shows them now.
11. Each moved action opens what it opened before: Clear data… its dialog, Start over… its confirmation (F0.10), Save
    layout as… its name prompt (F1.23). Their behavior doesn't change, only where they're found.

### Panels

12. **View › Panels** lists every panel with a tick while it's shown, docked or floating. Unticking closes it; ticking
    shows it where it was last, or in its default place when it was never moved (decision 7).
13. **Show all panels** shows every closed panel at its last or default place, without moving the open ones.
14. **Reset layout** puts every panel back in the default layout, as today (F1.0 behavior 10), after asking: "Put every
    panel back where it started? Your saved layouts aren't changed." It can be undone once, from the same menu
    (**Undo reset layout**) until the layout is changed again.
15. A panel closed from its own × says where to get it back the first time it happens, in a quiet note in the status
    bar: "Closed Packets. Show it again from View › Panels." Not again after that.

### Keyboard and accessibility

16. The menus are standard menus: arrow keys move, Enter chooses, Esc closes, access keys work, and a screen reader
    reads each item's name, its shortcut, its tick and why it's greyed out.
17. **Help › Keyboard shortcuts** lists every shortcut, from the same list of commands (behavior 3), grouped by menu.
    This spec adds only F10, F11, Ctrl+Q and the access keys; a full set of shortcuts can follow.
18. Menus use theme tokens only and work in every theme and palette at 200 % text; the menu bar wraps no item and
    scrolls no menu at 200 % in an 800-pixel-wide window.

## Service surface

- No engine changes: every command already exists as an `IEngineService` call or a UI action.
- In the UI, an `AppCommands` list: each command's id, name key, access key, shortcut, menu path, whether it's ticked,
  whether it can run and why not, and what it does. The menu bar, the macOS `NativeMenu`, the ☰ menu, the pills and the
  right-click menus are built from it.
- `PlatformServices` gains `MenuStyle`: `InWindow` (Windows, Linux), `System` (macOS), `Hamburger` (the browser).
- `AppearanceSettings` gains `AlwaysShowMenuBar`.

## APRS.NET dependencies

None.

## Desktop vs web differences

| | Windows and Linux | macOS | Web |
| --- | --- | --- | --- |
| Where the menus are | A bar above the top bar, hidden until Alt or F10 | The system menu bar | Under ☰ |
| Always show | View › Always show the menu bar | Always (system) | A bar on wide screens, optional |
| Quit, Full screen, Gather windows | Yes | Yes (Quit in the app menu) | No |

## Acceptance tests

1. On Windows and Linux the bar is hidden at start; Alt shows it with File selected, Alt+V opens View, F10 shows it,
   and Esc, a click outside or choosing a command hides it; with Always show on it stays.
2. On macOS the menus are in the system menu bar with About, Settings… and Quit in the app menu, and nothing is drawn in
   the window.
3. In the web app the ☰ button holds File, View, Station, Tools and Help, and Alt does nothing in the page.
4. Every command in the ☰ menu, the pills and the right-click menus is in a menu, with the same name, shortcut and
   greyed state; a test walks the command list and checks each menu built from it.
5. View › Panels ticks the open panels; unticking closes one, ticking shows it where it was; Show all panels shows the
   closed ones; Reset layout asks, resets and can be undone once.
6. Clear data…, Start over…, Save layout as… and About are reached from the menus and gone from Settings; each opens
   what it opened before.
7. Greyed commands give their reason to a screen reader; the menus work by keyboard alone; every theme and palette at
   200 % text passes the contrast and layout checks.

## Decisions for review

1. **Five menus: File, View, Station, Tools, Help** (agreed 2026-10-18). "Station" holds what acts on the station (switches,
   sending, sources, consoles); the alternative is spreading those over Tools and a Connection menu.
2. **Hidden until Alt on Windows and Linux** (agreed 2026-10-18), with Always show as an option.
3. **The system menu bar on macOS** (agreed 2026-10-18).
4. **Under ☰ in the web app** (agreed 2026-10-18), since Alt belongs to the browser; an always-shown bar is optional.
5. **The ☰ button stays everywhere** (agreed 2026-10-18), holding the same menus, so nobody needs to know about Alt.
6. **Actions leave Settings** (agreed 2026-10-18): Clear data, Start over, Save layout as, capture export and About
   move to the menus; Settings keeps only choices.
7. **Panels shown and hidden from View › Panels** (agreed 2026-10-18), with Show all panels. Agreed on top: Reset
   layout asks first and can be undone once (behavior 14), and the first panel closed says where to get it back
   (behavior 15).
8. **Few new shortcuts** (agreed 2026-10-18): F10, F11, Ctrl+Q and access keys only; a full shortcut set, and rebinding, can
   be a later feature.
9. **About as a dialog** (agreed 2026-10-18), not a Settings section.
