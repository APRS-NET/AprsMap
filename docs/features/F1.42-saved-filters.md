# F1.42 Saved filters

Status: built for 0.8.0 ([#457](https://github.com/APRS-NET/AprsMap/issues/457), maintainer request, 2026-10-27);
all six decisions by the maintainer. Each saved filter's conditions in Settings are shown in their text form
(behavior 9's line), the same words Copy filter gives.

## User story

As an operator at an EOC, during a storm I switch the map to **Storm spotting**: the Skywarn spotters list, weather
stations, and anything heard in the last 30 minutes, with the map on the county. After the storm I switch back to
**All**. At the MS150 I pick **MS150 route**: the volunteers list and the event's objects, on the route's area. I set
each up once, and recall it in one click, under pressure, without rebuilding the filter by hand.

## Background: what already exists

- The View filter (F1.9): conditions (kinds, categories, heard within, reception, capability, devices, Mic-E status,
  tags, problems), **All** and **My filter** to switch between everything and the last filter used, the chip on the map,
  per viewer and kept across sessions. Emergencies are always shown.
- Station lists (F1.33): named lists of callsigns and objects per profile, "Only stations in…" in the View filter, and
  a list in use joins the APRS-IS filter as `b/` and `o/`. Plain text in and out.
- The map remembers where it was per viewer (`MapViewState`: centre and resolution).

## Behavior

### Saving

1. **Save filter as…** in the Filter panel saves the conditions shown under a name ("Storm spotting"), with a tick
   **Use this map view** that also keeps the map's centre and zoom now (decision 3). Names are unique in a profile, up
   to 40 characters; up to 20 saved filters a profile.
2. **They belong to the profile** (maintainer, 2026-10-27), as station lists do: on a gateway, whoever may change
   settings (F2.9) saves, changes and deletes them, and every viewer can use them; switching profile switches the set.
   My filter stays the viewer's own.
3. **Station lists by reference**: a saved filter with "Only stations in" keeps the lists, not their entries, so
   editing a list changes every saved filter that shows it. Deleting a list takes it out of the saved filters that
   used it, and Settings says which.

### Using

4. **The chip is a menu**: the chip on the map (F1.9 behavior 4), and a **Filter** button beside it when nothing is
   filtered, open a menu with **All**, **My filter** and each saved filter, the one in use ticked. The chip names it:
   "Storm spotting · 42 of 2,140". The View menu (F1.29) has the same choices under **Filter**, and **Next filter**
   (Ctrl+Shift+F) goes round them in order (decision 4).
5. **Switching to a saved filter** shows its conditions in the Filter panel and applies them; with a map view, the map
   moves there; without one, the map stays where it is. Per viewer: each browser on a gateway uses its own choice, kept
   across sessions like My filter.
6. **Using it doesn't change it**: changing a condition while a saved filter is in use makes the chip say "Storm
   spotting (changed)", and the panel offers **Save** (over it, for whoever may change settings), **Save as new…**, and
   **Back to saved**. For a viewer who may not change settings, the changed conditions become their My filter.
7. **Receiving what it shows**: a saved filter in use with station lists joins the APRS-IS filter exactly as the lists
   do (F1.33 behavior 9), since it's the viewer's filter in use. Emergencies are always shown (F1.9 behavior 3).

### Managing

8. **Settings › Lists and filters** (Settings › Station lists, renamed): the station lists as now, then the saved
   filters in order, each with **Rename**, **Delete** (with Undo, as profiles have), **Move up** and **Move down**, the
   conditions in words ("Lists: Skywarn spotters · Weather · Heard in the last 30 minutes"), and whether it moves the
   map.
9. **Plain text in and out**, like lists (F1.33 behavior 3): **Copy filter** puts it on the clipboard as one readable
   line, such as `lists: Skywarn spotters; categories: weather; heard: 30 min; view: 38.9 -94.7 z10`, and **Paste
   filter…** in Settings adds one from that text under a new name, pointing at the parts it can't read and at lists
   this profile doesn't have. Lists are named, not identified, so a filter can go to another profile or station.

## Service surface

- `SavedFilter(Id, Name, StationFilter Filter, SavedMapView? View)` and `SavedMapView(Latitude, Longitude, Zoom)`;
  `StationProfile.SavedFilters` (null for none), saved with the settings. Errors: `settings.saved-filter.name-taken`,
  `settings.saved-filter.too-many`, `settings.saved-filter.name-invalid`.
- `SavedFilterText.Format(SavedFilter, lists)` and `Parse(string, lists)` in Contracts, so every app reads and writes
  the same text; errors by part.
- The viewer's choice (All, My filter, or a saved filter's id) is a per-viewer preference beside the View filter's
  (F1.9 behavior 7).

## APRS.NET dependencies

None.

## Desktop vs web differences

| | Desktop | Web (gateway) |
| --- | --- | --- |
| Saving, changing, deleting | The user | Whoever may change settings (F2.9) |
| Using one | The user | Each browser, its own choice |
| Its map view | Moves the desktop's map | Moves that browser's map |

## Acceptance tests

1. Saving "Storm spotting" with lists, weather and 30 minutes, then switching to All and back, shows the same stations;
   with Use this map view, the map moves to where it was saved.
2. Editing the Skywarn spotters list changes what Storm spotting shows.
3. Changing a condition while it's in use shows "(changed)"; Back to saved restores it; Save overwrites it for every
   viewer.
4. A gateway viewer who may not change settings can use saved filters but not save, rename or delete them.
5. Next filter goes All → My filter → each saved filter → All.
6. Copy filter's text pasted into another profile gives the same conditions, with a list that profile lacks pointed out.
7. A saved filter with a station list in use adds the list's `b/` part to the APRS-IS filter.

## Decisions for review

1. **Saved filters are per profile** (maintainer, 2026-10-27), shared on a gateway; My filter stays per viewer.
2. **An optional map view per filter** (maintainer, 2026-10-27), apart from saved layouts (F1.23), which arrange panels.
3. **The map view is unticked by default** (maintainer, 2026-10-28): most filters are about who, not where.
4. **Ctrl+Shift+F for Next filter** (maintainer, 2026-10-28): Ctrl+F is Find a station (F1.29); F1.29 decision 8 keeps
   new shortcuts few, and this one earns its place by being used under pressure.
5. **Up to 20 a profile** (maintainer, 2026-10-28), matching station lists' limit of lists.
6. **Text names lists, not their ids** (maintainer, 2026-10-28), so a filter moves between profiles and stations; a list
   the profile lacks is pointed out on paste, not created.
