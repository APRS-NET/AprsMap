# F0.5 First-run wizard

Status: built, the map picker (behavior 5's last way in) in 0.4.0-alpha.1
([#130](https://github.com/APRS-NET/AprsMap/issues/130)). Use a TNC instead on the server step comes with F3.1.

## User story

As a new user, I open the app and, in under a minute and at most four short steps, give it my callsign and where my
station is, so that it connects to APRS-IS as me and shows the map around me. I can skip anything that isn't needed to
start receiving.

## Behavior

### When it appears

1. The wizard opens when the engine has no station profile (`AppSettings.Profiles` is empty; the status is
   `NotConfigured`) and the settings are writable (`AppSettings.ReadOnly` is false). It covers the main view; the main
   view is not usable behind it.
2. On a gateway whose settings are read-only (no operator sign-in, `Gateway:AllowSettingsChanges` off), browsers do not
   get the wizard. The status bar says the gateway isn't set up, and a short note explains that its operator sets the
   first callsign (for example with `Engine__Callsign`; [deployment.md](../deployment.md)).
3. The wizard can be closed without finishing. The app then stays not set up, and the status bar offers to open the
   wizard again. Nothing is saved until the last step.
4. The same steps, started from Settings, create an additional profile (F0.8). That variant has a profile name field
   (default: the callsign) and does not change the active profile unless the user ticks "Switch to it now".

### Step 1: Callsign

5. One field: callsign with optional SSID (for example `N0CALL-9`). It is trimmed and upper-cased as the user types.
6. "Next" is enabled once the field is non-empty. Format errors are shown inline from the engine's validation on save
   (behavior 29); the wizard only checks emptiness and the known placeholders: `N0CALL` and `NOCALL` (any SSID) are
   refused with "Use your own callsign; APRS-IS servers reject this one."
7. A help line explains the SSID in one sentence and links to the APRS SSID conventions (source: APRS101 / SSID
   recommendations).

### Step 2: Location

8. The location is optional: "Skip for now" moves on with no location. The map and filters work without it (the
   automatic filter follows the map, F1.2); distance and bearing from me (F1.6) appear once it is set.
   Before the map reports its view, a profile logs in with my range around this location (`r/<lat>/<lon>/150` by
   default) or, with no location, `m/150` (around the callsign's last position on APRS-IS). On the user-defined
   filter port, a login with no filter receives only messages addressed to it, so a new profile would otherwise show
   nothing (found in use, 2026-10-15).
9. The step offers these ways, as tabs or a segmented choice. Each one produces a latitude and longitude, shown in a
   confirmation line (decimal degrees, and the 6-character Maidenhead locator) before "Next":
   1. **Maidenhead locator**: 4, 6, 8 or 10 characters, case-insensitive. The position is the centre of the square.
      Invalid input shows why (wrong length, or a character out of range for its position).
   2. **Address or postal code**: a free-text field and a "Look up" button (behaviors 13–22).
   3. **Coordinates**: one field accepting decimal degrees (`40.0150, -105.2705`, or with N/S/E/W) or degrees and
      decimal minutes (`40 00.90 N 105 16.23 W`). Latitude first. Out-of-range values are rejected.
   4. **This device's location**: in the browser, the browser's geolocation API, after its own permission prompt. It is
      the viewer's location, which on a gateway may not be the station's, so the confirmation line says so. On desktop
      this choice appears only once the OS location API exists (F3.6).
   5. **Pick on the map**: a modal map with a fixed crosshair in the centre; the user pans and zooms under it, and
      "Use this point" takes the centre. Shown only once the map control exists (F1.4).
10. Switching between ways keeps the last confirmed position until another way confirms a new one.
11. The wizard never stores the text the user typed to find a location (address, postal code), only the resulting
    coordinates.
12. When the step is shown with a confirmed position, it is the profile's `Latitude`/`Longitude`.

### Address lookup (Nominatim)

13. Lookups go to a Nominatim server, by default `https://nominatim.openstreetmap.org`. The endpoint is configurable
    (`Geocoding:Endpoint`), for example to a self-hosted Nominatim. An empty endpoint turns lookup off and hides the
    choice.
14. Before the first lookup in a session, a one-line notice under the field says that the text is sent to the
    configured server (its host name shown), and links to its usage policy. Nothing is sent until the user presses
    "Look up" (or Enter in the field).
15. **No autocomplete**: one request per explicit "Look up", never while typing.
16. **Rate**: the engine sends at most one request per second, across all callers. A lookup that arrives sooner waits
    (up to 1 s); a second one arriving while one waits replaces it.
17. **Identification**: requests carry the app's own User-Agent, from branding (`Brand.Slug`/`Brand.Version` and
    `Brand.SourceUrl`, as `slug/version (+source URL)`), never a library or browser default. Browsers don't call Nominatim directly; the request
    goes through the engine (on the web, the gateway).
18. **Caching**: results are cached in memory by normalised query (trimmed, case-folded, whitespace collapsed) for the
    life of the engine process, so repeating a query sends nothing. The cache is never written to disk (behavior 11).
19. The request asks for at most 5 results, in the user's language (`Accept-Language` from the UI culture), JSON
    format, no extra details. The user picks one from the list (display name as returned); a single result is
    preselected. "No match" says so and suggests a postal code with country, or another way.
20. **Attribution**: the result list shows "Search by Nominatim · © OpenStreetMap contributors" with a link to
    <https://www.openstreetmap.org/copyright>.
21. Network errors, HTTP errors, and a rate-limit or block response (HTTP 429/403) show a short message and leave the
    other ways available. The engine backs off for 60 s after a 429/403 and answers lookups in that window with the
    same message, without sending.
22. Queries and results are not logged above Debug level, and never with the user's identity.

### Step 3: Server

23. Default: `rotate.aprs2.net:14580` (the worldwide Tier 2 rotate). A short list offers the regional rotates
    (`noam`, `soam`, `euro`, `asia`, `aunz` `.aprs2.net:14580`), plus free entry of `host` or `host:port`. Most users
    press Next. The list and its region names come from APRS.NET (`AprsIsEndpoint`'s presets), not from this app.

### Step 4: Passcode

24. Optional. Two choices: "Receive only (no passcode)", selected by default and explained in one sentence (the app can
    see everything but can't transmit to APRS-IS), and "I have a passcode".
25. **I have a passcode**: the user types it, a number from 0 to 32767. The app never fills this field in.
26. **Passcode calculator**: next to the field, a link "Don't have one? Calculate it" opens a small dialog:
    1. It shows the base callsign from step 1 (read-only; the SSID doesn't change the passcode) and a required tick box,
       "I'm a licensed amateur radio operator and this is my own callsign." "Calculate" is disabled until it is ticked.
    2. "Calculate" asks the engine (APRS.NET `AprsIsPasscode.Compute`) and shows the number with a "Copy" button that
       puts it on the clipboard. It does not fill in the passcode field; the user pastes or types it there.
    3. A short line says the passcode is not a secret or a password, only the APRS-IS sign that the operator is licensed,
       and that the same number works in other APRS-IS software.
    4. The tick is not stored; the dialog asks again each time it opens. Closing it returns to the step unchanged.
    5. In the browser, "Copy" needs the clipboard, which browsers allow only on HTTPS or localhost. Where it isn't
       available the button is hidden and the number stays selectable.
27. A passcode doesn't transmit anything by itself anything by itself: transmitting also needs F2.1 and, on a
    gateway, operator sign-in.

### Finish

28. "Finish" saves one profile through `SaveSettingsAsync`: id new, name = callsign (or the name from behavior 4),
    callsign, passcode (-1 when receive-only, otherwise the one entered), server, no filter, location if set; it becomes the active profile.
    Units are set at the same time from the UI culture's region: US, Liberia and Myanmar get `UnitSettings.Imperial`,
    everyone else `UnitSettings.Metric`; they can be changed later in Settings.
29. If the engine rejects the settings (`ArgumentException`), the wizard returns to the step the message concerns
    (callsign or server) and shows the message there. Other failures show the message and keep everything entered.
30. After a successful save the wizard closes; the engine connects with the new profile (F0.4) and the status bar shows
    it.

### Accessibility and appearance

31. Every step works with the keyboard alone (Tab order follows the visual order; Enter = Next; Esc = close, with a
    confirmation only if something was entered). Focus starts in the step's first field.
32. Text and controls use theme tokens only, and the wizard works at 200 % text size and in every palette
    ([ux](../ux/README.md#appearance-and-accessibility)). Product name text binds to `Brand.DisplayName`.

## Service surface

- Used: `IEngineService.GetSettingsAsync`, `SaveSettingsAsync`, `GetStatusAsync` (F0.4).
- Added: `Task<int> ComputePasscodeAsync(string callsign, CancellationToken)` for behavior 26, because the UI references
  only Contracts and the algorithm lives in APRS.NET. It throws `ArgumentException` for a callsign APRS.NET can't hash.
  On the gateway it has the same gate as `SaveSettings` (behavior 2).
- Added: `Task<IReadOnlyList<GeocodeResult>> GeocodeAsync(string query, string? language, CancellationToken)` with
  `GeocodeResult(string DisplayName, double Latitude, double Longitude)`. The UI passes its language because on the
  web the engine runs on the gateway and can't see the browser's. A blank query returns nothing without sending.
  Throws `InvalidOperationException` with a user-readable message for behavior 21 (and when a newer lookup replaces a
  waiting one, behavior 16); `UnauthorizedAccessException` on a read-only gateway.
- Added: `Task<GeocodingInfo> GetGeocodingInfoAsync(CancellationToken)` with `GeocodingInfo(bool Enabled, string?
  Host, string? UsagePolicyUrl)`, for behaviors 13–14. A read-only gateway reports it disabled, so the wizard hides
  the address choice there.
- Added: `GetServerPresetsAsync()` → `ServerPreset(Key, Name, Server)` from APRS.NET's `AprsIsServerPreset.All`, for
  behavior 23. The UI shows a translated region name looked up by `Key`, falling back to the English `Name`.
- Added: `ParseLocatorAsync(locator)` → `LocatorInfo(Locator, Latitude, Longitude)` (the square's centre) and
  `GetLocatorAsync(latitude, longitude)` → the 6-character locator, for behavior 9.1 and the confirmation line. The UI
  references only Contracts, so APRS.NET's `MaidenheadLocator` is reached through the engine. A bad locator raises
  `maidenhead.empty`, `maidenhead.wrong-length` or `maidenhead.invalid-character` (with the character, its position and
  its pair: `field`, `square`, `subsquare`…). Neither is operator-only: they send nothing anywhere.
- Coordinates typed by the user (behavior 9.3) are parsed in the UI: it is input syntax, not geodesy.
- This device's location (behavior 9.4) is not an engine capability: it is the viewer's device, so it is a platform
  service like the clipboard. `AprsMap.UI.Platform.IDeviceLocation` is supplied by each app: the browser app's uses the
  geolocation API through `main.js` (with reasons: refused, unavailable, timed out, not a secure page, unsupported);
  the desktop app supplies none until F3.6, and the choice is hidden.
- Configuration: `Geocoding:Endpoint` (default the public Nominatim server; empty turns lookup off),
  `Geocoding:UsagePolicyUrl` (default: the OSMF policy for the public server, none for others), `Geocoding:Timeout`
  (10 s).
- The engine owns the Nominatim client (MIT `AprsMap.Core`; `IHttpClientFactory`, `TimeProvider` for the rate limit
  and back-off). On the gateway the hub method has the same gate as `SaveSettings` (behavior 2), so the gateway is not
  an open geocoding proxy.

## APRS.NET dependencies

- **G08, Maidenhead part** (locator ↔ latitude/longitude) for behavior 9.1 and the confirmation line: delivered in
  APRS.NET `0.1.0-alpha.12` as `MaidenheadLocator`; its `MaidenheadParseError` gives the reason for behavior 9.1.
- **G02, passcode part** for behavior 26: delivered in `0.1.0-alpha.10` as `AprsIsPasscode.Compute`.
- **G26, server presets with region names**, for behavior 23: delivered in `0.1.0-alpha.12` as
  `AprsIsServerPreset.All`.
- None for the rest: callsign and login validation already come from `AprsIsClientOptions.Validate` (F0.4).

## Desktop vs web differences

| | Desktop | Web |
| --- | --- | --- |
| When shown | No profile | No profile and settings writable; otherwise the "operator sets it up" note |
| This device's location | After F3.6 (OS location API) | Browser geolocation, with the "viewer's location" caveat |
| Address lookup | Engine in-process calls Nominatim | Gateway calls Nominatim; same gate as saving settings |

## Acceptance tests

1. With no profile and writable settings, the wizard opens; with a profile, it doesn't; on a read-only gateway the
   note shows instead (view-model and gateway tests).
2. `N0CALL`, `nocall-5` are refused at step 1; `n0abc-9 ` becomes `N0ABC-9`.
3. Locator `DN70` → centre of the square; `dn70kb` → its 6-character centre; `DN7` and `DN70ZZ` are rejected with a
   reason.
4. Coordinate parsing: decimal with signs, decimal with hemispheres, degrees-decimal-minutes; latitude 91 rejected.
5. Geocoding against a fake HTTP handler: the request has the app's User-Agent, `format=jsonv2`, `limit=5`,
   `Accept-Language`; two identical queries send one request; two different queries 0.2 s apart are sent ≥ 1 s apart
   (fake clock); a 429 makes the next lookups within 60 s fail without a request; an empty endpoint disables lookup.
6. The gateway refuses `Geocode` and `ComputePasscodeAsync` when settings are read-only.
7. Passcode step: receive-only is the default and saves -1. In the calculator, "Calculate" stays disabled until the tick
   box is ticked; the result is shown with "Copy" and the passcode field stays empty; `n0call-9` and `N0CALL` give the
   same number as APRS.NET; reopening the dialog clears the tick.
8. Finish saves exactly one active profile with the entered values, receive-only as -1, and units from the culture
   (en-US → Imperial, en-GB → Metric); an engine rejection returns to the right step with its message.
9. Keyboard-only run through all steps (headless UI test); 200 % text and high-contrast render without clipping.

## Decisions

Resolved in review (maintainer, 2026-10-14):

1. Maidenhead conversion goes into APRS.NET first (part of G08); no shim.
2. The regional server list comes from APRS.NET.
3. Geocoding results are cached in memory only, never persisted.

Resolved after review (maintainer, 2026-10-14):

4. The user always enters their own passcode. The wizard links to a built-in calculator (behavior 26) instead of only
   pointing elsewhere: the algorithm is public and widely published (Xastir ships it as `callpass`; online calculators
   and APRS.NET publish it), so sending users to a third-party calculator adds a step without adding a check. The
   calculator needs a "licensed operator, own callsign" tick each time, and offers "Copy" rather than filling in the
   field, so entering the passcode stays a deliberate act. Receive-only stays the default.

  be cached; no autocomplete; no systematic or bulk queries, and periodic requests from apps count as bulk; visible
  attribution under ODbL; heavy users self-host or use a commercial provider.

- Passcode practice, for decision 4 (all accessed 2026-10-14):
  - APRS-IS, <https://www.aprs-is.net/Connecting.aspx>: "It is the responsibility of each software author to provide

    that it "is available from some open-source locations".

    passcodes, because "issuing a passcode has to be a manual process involving a check if you are a licensed Radio
    Amateur". Users request one from the project or a local IGate operator.
  - Xastir `callpass(1)`, <https://manpages.debian.org/buster/xastir/callpass.1.en.html>: a command-line tool shipped
    with Xastir that prints the passcode for any string.
