# F0.8 Station profiles in Settings

Status: draft

## User story

As an operator with more than one station identity (home and portable, a club callsign, an event SSID), I keep each
one as a profile with its own callsign, passcode, server, filter and location. I add, change, copy and remove them in
Settings, and switch between them from Settings or the status bar. Switching reconnects to APRS-IS as the other
station.

Already built (F0.4): the profile model and storage, switching from the status bar, and reconnecting on a switch. This
feature adds managing them.

## Behavior

### The Profiles section

1. Settings (F0.6) gets a **Profiles** section, first in the list: Profiles, Appearance, About.
2. It lists every profile in the stored order: its name, callsign, server (the region name for a preset, otherwise
   `host:port`), and its location's 6-character locator when it has one. The active profile is marked "Active" in
   text, not only by colour.
3. Each profile has **Use** (switch to it; hidden on the active one), **Edit**, **Copy** and **Delete**. An **Add
   profile** button is under the list.
4. On a gateway whose settings are read-only (F0.4: no operator sign-in, `Gateway:AllowSettingsChanges` off), the list
   is shown but every action is hidden, with a one-line note that the gateway's operator manages its profiles.

### Adding and editing

5. **Add profile** opens the setup wizard (F0.5) in *add* mode, over Settings. It is the same four steps, plus:
   1. a **Profile name** field on the first step, under the callsign. It defaults to the callsign while the user hasn't
      typed a name of their own;
   2. an optional **Filter** field on the server step, with one line of help: empty means 150 km around the profile's
      location (the stand-in until F1.2), or a link to the APRS-IS filter syntax;
   3. a **Switch to it now** tick on the last step, off by default (F0.5 behavior 4).

   Finish adds the profile at the end of the list. Units and appearance aren't touched.
6. **Edit** opens the wizard in *edit* mode, filled in from the profile: name, callsign, location (with its confirmation
   line), server (the matching region, or Another server), filter, and passcode (receive only for -1; otherwise "I have
   a passcode" with the number). Finish replaces the profile in place, keeping its id. If it is the active profile and
   its login, server or filter changed, the engine reconnects (F0.4); renaming or moving the location doesn't.
7. In both modes the wizard's title says what is happening ("Add a profile", "Edit Home"). Closing without finishing
   changes nothing, and asks first if anything was changed (F0.5 behavior 31).
8. A rejection from the engine goes back to the step it is about (F0.5 behavior 29), including a duplicate name
   (`settings.profile.name-duplicate`), which goes to the name field.

### Copy, delete, switch

9. **Copy** adds a copy right after the original, with a new id and the name "*name* (copy)", or "(copy 2)" and so on
   until it is unique, and opens it in the editor. The copy isn't active.
10. **Delete** removes the profile at once and offers **Undo** for 10 s, like Reset appearance (F0.6 behavior 5).
    Deleting the active profile makes the first remaining one active, and the engine reconnects as that station. The
    only profile can't be deleted: Delete is disabled with a tooltip saying why. Without a profile the app would be
    back to not set up.
11. **Use** switches exactly as the status bar picker does (F0.4): the engine disconnects and reconnects with that
    profile. The status bar and the list update together.

### Saving

12. Every change saves the whole settings at once through `SaveSettingsAsync`, so the engine validates it (F0.4) and
    another window or browser sees it on its next status poll. A failure leaves the list as it was and shows the
    engine's reason, translated (F0.9).
13. Queued outgoing items (messages, beacons, objects; Phase 2) stay with the profile they were made under; nothing is
    sent under another callsign (scope, "Settings storage and profiles"). Nothing in Phase 0 queues anything yet.

### Accessibility

14. The section works with the keyboard alone. Each action's accessible name includes the profile ("Edit Home"), and
    Undo takes focus after a delete. Text and controls use theme tokens and translated strings, and fit at 200 % text
    (F0.6 behavior 21).

## Service surface

- No `IEngineService` change: `GetSettingsAsync` and `SaveSettingsAsync` (F0.4) carry everything. The gateway's
  read-only gate applies as it does to switching.
- `SetupWizardViewModel` gains a mode (first run, add, edit), the profile name, the filter and "Switch to it now".

## APRS.NET dependencies

None. The filter is free text checked by APRS.NET's `AprsIsClientOptions.Validate` (control characters); a typed filter
builder is G04, for F1.2.

## Desktop vs web differences

None beyond F0.4's: on a read-only gateway the section only lists.

## Acceptance tests

1. Profiles lists every profile with name, callsign, server and locator, and marks the active one in text.
2. Add: the wizard opens with a name defaulting to the callsign; Finish appends one profile, active only with the tick;
   units unchanged.
3. Edit: the wizard opens filled in; Finish replaces the profile with the same id; editing the active profile's server
   reconnects, renaming it doesn't (engine test).
4. A duplicate name is refused and shown on the name field.
5. Copy makes "Home (copy)", then "Home (copy 2)", inactive, and opens the editor.
6. Delete with Undo; deleting the active profile activates the first remaining one; the only profile can't be deleted.
7. On a read-only gateway the section lists without actions (view-model and gateway tests).
8. Keyboard only: add, edit, copy, delete with Undo, and switch, without the mouse (headless).
9. All of it fits at 200 % text in every palette (the F0.6 render check).

## Decisions for review

1. **Reordering**: move up and down in the list, or keep the order profiles were added in? Proposed: later, when there
   is a use for the order beyond display.
2. **Settings search**: F0.6 left it to this feature. Profiles aren't registry options, so search still has only the
   Appearance options to find. Proposed: wait until Phase 1 adds more sections.
