# F1.33 Station lists

Status: spec'd for 0.7.0 ([#328](https://github.com/APRS-NET/AprsMap/issues/328)); decisions 1 and 2 by the maintainer (2026-10-20), the rest proposed.

## User story

As an operator working an event, I keep a list of the volunteers' callsigns and our objects, and show only them on
the map, wherever they are. As an EOC operator during a weather event, I show only the weather spotters I work with.
I paste a list in from an email or a roster, copy it out to a text file or another profile, and switch it on and off
in a click.

## Background: what already exists

- The View filter (F1.9): kinds, categories, heard within, reception, device class, Mic-E status, tags and more, per
  viewer; emergencies always shown. Nothing filters by callsign.
- The APRS-IS filter (F1.2): my range, the map's view, followed and watched stations (`f/`), and the source's own
  text, where `b/` (buddy list, with `*`) and `o/` (objects) can be typed by hand.
- Profiles (F2.1) carry what belongs to one station set-up: callsign, beacons, objects (F2.7).

## Behavior

### Lists

1. **Each profile has its own station lists** (maintainer, 2026-10-20), in Settings › Station lists: a name ("MS150
   volunteers", "Skywarn spotters") and its entries. Proposed: up to 20 lists, up to 500 entries each.
2. **An entry** is one of:
   1. a callsign with its SSID (`KD0XYZ-7`);
   2. a callsign without an SSID, meaning every SSID of it (`KD0XYZ`);
   3. a prefix and `*` (`WA0RC*`), meaning anything starting so;
   4. an object or item name (`AID-3`), matched against objects' and items' names as well as callsigns.
   Case doesn't matter. Proposed: an entry can have a note after it (`KD0XYZ-7 Sweep 2`), kept with it and shown in the
   list editor and the station's details.
3. **Plain text in and out** (maintainer, 2026-10-20): the editor is a text box with one entry a line, the note after a
   space; blank lines and lines starting with `#` are ignored (and kept, so a pasted roster keeps its headings).
   **Copy list** puts the whole list on the clipboard as that text, ready for Notepad, an email or another profile;
   **Paste** (or typing) replaces it. Entries that can't be a callsign or a name are pointed out by line, and the list
   can't be saved until they're fixed or removed.
4. **Copy to profile…** copies a list into another profile in one step (proposed), as an alternative to copy and paste.
5. **Add to list** in a station's Details and on the map's right-click on a station adds it to a list of the active
   profile (proposed), with the list chosen from a menu.

### Showing only a list

6. **The View filter gains "Only stations in…"** with the active profile's lists (proposed: one or more lists,
   shown together). With it set, the map and the station list show only the stations and objects the lists match;
   every other condition still applies on top.
7. **Others are hidden** (proposed), not dimmed: dimmed stations still crowd a busy map, and Show all is one click
   away. Emergencies are always shown, as now (F1.9 behavior 3).
8. The filter chip on the map says which list is showing ("MS150 volunteers"), as it says a filter is on today.

### Receiving them wherever they are

9. **A list in use joins the APRS-IS filter** (proposed): its callsign entries as a buddy list (`b/`, with `*` as
   written), its names as objects (`o/`), so a spotter far outside my range is still received. Only while the list is
   shown in a viewer's filter; on a gateway, a browser's lists count up to the gateway's limit, as watched stations do
   (F1.16). A filter has a length limit on APRS-IS (F1.2), so a list too long for it is sent in part, and the Settings
   page says so.

### Later

10. **Alerts and tactical names** (F4.7) use the same lists: "tell me when anyone on this list is heard", and showing an
    entry's note as its tactical name. Not in this feature.

## Service surface

- `StationList(Id, Name, Entries)` with `StationListEntry(Pattern, Note)`; `StationProfile.StationLists`.
- `StationFilter.Lists` (`IReadOnlyList<string>?`, list ids).
- `StationListText.Parse(string)` and `Format(StationList)` in Contracts, so the desktop, the browser and the engine
  read and write the text the same way; errors by line.
- Error codes: `settings.station-list.entry-invalid` (with the line), `settings.station-list.too-many`,
  `settings.station-list.name-taken`.

## APRS.NET dependencies

None: the `b/` and `o/` filter parts are in G04 (delivered).

## Desktop vs web differences

| | Desktop | Web (gateway) |
| --- | --- | --- |
| Editing lists | The user | Whoever may change settings (F2.9) |
| Showing only a list | The user | Each browser, its own filter |
| Copy list | The clipboard | The browser's clipboard |

## Acceptance tests

1. Pasting a roster with headings, blank lines, notes and one bad line points at the bad line; fixed, it saves, and
   Copy list gives back the same text.
2. `KD0XYZ` matches KD0XYZ-7 and KD0XYZ; `WA0RC*` matches WA0RC-11; `AID-3` matches the item AID-3.
3. Only stations in "Spotters" shows the spotters and nobody else, except an emergency.
4. With the list shown, the APRS-IS filter carries `b/` and `o/` parts for it; switched off, they leave.
5. Copy to profile puts the list in the other profile; each profile keeps its own.

## Decisions for review

1. **Lists are per profile** (maintainer, 2026-10-20).
2. **Plain text in and out, easy to copy to Notepad or another profile** (maintainer, 2026-10-20).
3. **Others hidden, not dimmed** (proposed).
4. **A list in use joins the APRS-IS filter** as `b/` and `o/` (proposed).
5. **Notes on entries**, shown now and used as tactical names with F4.7 (proposed).
6. **Up to 20 lists of 500 entries** (proposed).
7. **Add to list from Details and the map** (proposed).
