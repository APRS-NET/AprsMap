# F1.23 Saved layouts

Status: built for 0.5.0 ([#195](https://github.com/APRS-NET/AprsMap/issues/195)). The app menu lists **Use layout
NAME** for each saved layout and **Save layout as…**, which opens **Settings › Layout**: a name and Save layout as, each
saved layout with Use, Update, Rename and Delete, and **Ask to use a saved layout when the monitors change** (on). A
saved layout keeps F1.0's saved form (panels, floating windows and the main window's place) and the monitor setup
(`WindowPlacement.Fingerprint`) it was last used with; using one closes the floating windows open, restores it fitted to
the screens there are, and moves the main window. When the monitors change, at start-up (against the monitors the app
last saw) or while running, and a saved layout was last used with the new setup, a bar asks "Monitors changed. Use
layout Desk?" with **Use**, **Keep current** and **Don't ask again for these monitors**. Kept per viewer under
`layouts`; one that can't be read is left out with a note, and an unreadable file is set aside.

## User story

As an operator who moves between a laptop on its own and a desk with more monitors, I save a layout for each and get
the right one back without rebuilding it. When I plug in or unplug a monitor, the app offers the layout I last used
with that setup.

## Behavior

1. **Save layout as…** (app menu) names the current layout (F1.0). Saved layouts can be applied, renamed, updated with
   the current arrangement, and deleted, from the app menu and from Settings › Layout.
2. Each saved layout records the **monitor setup** it was last used with: the screens' sizes, positions and scaling.
3. **When the monitor setup changes** (at start-up or while running), and a saved layout was last used with the new
   setup, the app **asks**: "Monitors changed. Use layout *Desk*?" with **Use** and **Keep current**. It never switches
   by itself.
   - With no saved layout for the new setup, nothing is asked. Windows are still kept on screen (F1.0 behavior 12).
4. **Don't ask again for this setup** (on the prompt) remembers Keep current for that setup. Settings › Layout can turn
   the question off entirely.
5. Saved layouts are per viewer and stored with the current layout (F1.0 behavior 8), with the same reading rules: one
   that can't be read is dropped with a note, not a failure.
6. In the browser, the monitor setup is the browser window's screen as the browser reports it. Usually that's one
   screen, so the prompt rarely appears.

## Acceptance tests

1. Save as, apply, rename, update and delete; saved layouts survive a restart.
2. With a fake screen list: changing to a setup with a saved layout prompts once; Use applies it; Keep current doesn't;
   "Don't ask again" stops the prompt for that setup only.
3. A setup with no saved layout prompts nothing, and stray windows are still brought on screen.
4. The prompt and the layout list work from the keyboard and at 200 % text in every palette.
