# F1.34 Components and versions in About

Status: built for 0.6.0 ([#351](https://github.com/APRS-NET/AprsMap/issues/351)); decisions proposed 2026-10-21 for the
maintainer's review. In the UI: Help › About › **Components**.

## User story

As a user filing a bug, or a gateway operator checking what's deployed, I open About and see exactly which APRS.NET
packages and libraries, at which versions, the app I'm using is built from, and what it's running on, and copy all of
it into the report in one click.

## Background: what already exists

- Help › About (F1.29, F1.31): the app's version, the engine and APRS.NET versions, the connection, the folders, the
  licence and credits.
- The release's SBOMs (F4.17): every package of each app, from the same restore the build uses.

## Behavior

1. **Components** is a part of About, closed until opened ("Components (98)"): for each app, a heading with its
   version ("Desktop app 0.6.0-alpha.1 (3f7c561)"), the .NET runtime and OS it's running on, then each component on
   a line with its version and licence: the .NET shared frameworks first, then every package the app copies to its
   output, by name, every `AprsNet.*` among them. A licence is what the package states: an SPDX expression ("MIT"),
   "licence file in the package", or "licence not stated".
2. **Which apps**: on the desktop, the desktop app's (engine and UI in one). In a browser, the browser app's own; and,
   for the signed-in operator, the gateway's as well, since they can differ while a gateway is being updated.
3. **The gateway's list is the operator's** (proposed): a viewer isn't told the server's exact package versions, which
   help no viewer and would help an attacker; the engine's version is still shown as before.
4. **Copy list** puts every list shown on the clipboard as plain text, a line a component in columns, for a bug report.
5. **Licences in full**: a link to the releases, whose SBOMs (F4.17) carry each licence, with its text where the
   package ships one.
6. **From the build, not by hand**: the build writes the list (`build/Components.targets`) from the packages the app
   copies to its output, each licence from its package's own metadata, and embeds it in the app; CI checks each app's
   list against its SBOM, so About and the SBOM never disagree (F4.17 behavior 5).

## Service surface

- `ComponentReport` (host, version, runtime, OS, components) and `ComponentInfo` (name, version, licence, framework),
  with `ComponentReport.Of(assembly)` reading the embedded list, in Contracts.
- `IEngineService.GetComponentsAsync()`: the engine app's report; operator-only on a gateway (`gateway.operator-only`).

## APRS.NET dependencies

None.

## Desktop vs web differences

| | Desktop | Web (gateway) |
| --- | --- | --- |
| Lists shown | The desktop app's | The browser app's; the gateway's too for the operator |

## Acceptance tests

1. The gateway's embedded list names it the gateway, has both shared frameworks and the `AprsNet.*` packages with
   their licences, and no Avalonia (the UI is the browser's).
2. On the desktop one list shows, with its version, runtime, OS and licences in words.
3. A viewer of a gateway sees the browser app's list and is refused the gateway's; the operator sees both.
4. Copy list gives the lists as text in columns.
5. CI: each app's list agrees with its SBOM.

## Decisions for review

All proposed (2026-10-21), built as described so they can be tried:

1. **Closed until opened**, inside About: a hundred lines would bury the rest.
2. **Runtime packages only** in About (what the app copies to its output); the SBOM also lists build-time packages.
3. **The gateway's list for the operator only.**
4. **Licences as each package states them**, never filled in by hand.
5. **Full licences via the release's SBOM**, not a notices file shipped in the app.
