# F1.4 Map

Status: built ([#67](https://github.com/APRS-NET/AprsMap/issues/67))

Built: the tile cache (`AprsMap.Tiles`) and the gateway's `/tiles` endpoint (behaviors 8–11, #86); the map as the
shell's centre, its opening position, Home, navigation by mouse, wheel and keys, the attribution, the ground colour while
tiles load, dimming in a dark theme, and the browser's GPU budget (behaviors 1–3, 5, 7, 12, 13, #87). Then
Fit, the stations from a symbol atlas, labels that never overlap, selection, hover text and fading of stale stations
(behaviors 4, 14–20). Then Settings › Map (behavior 21): provider, map fade, labels, symbol size, and the station's fade and
remove times (F1.3 behavior 9). Then map contrast from a map button (behavior 13, [#345](https://github.com/APRS-NET/AprsMap/issues/345)). Then the performance check (acceptance test 7, [results](#performance-check)): the
browser holds 60 frames a second with 2,000 stations; the desktop run is still to be recorded. Decided with the
milestone: AOT for the browser's Release build, wind barbs move to F1.10, and labels show where they fit (decisions
1, 2 and 4, as proposed).

## User story

As an operator, I see the stations around me on a map: each with its APRS symbol and callsign, moving as packets
arrive, over a familiar street or terrain map. I pan and zoom freely, on desktop and in the browser, and the map stays
smooth with a busy APRS-IS feed. It follows my theme, and it never breaks the tile provider's rules.

## Behavior

### The map in the window

1. The map becomes the main surface (UX principle 1): the fixed centre of the shell (F1.0), with panels such as the
   packet list docked around it.
2. **Opening position**:
   - the last view this viewer left (centre and zoom), saved with their appearance preferences (F0.6);
   - otherwise the active profile's location, fitted so the view's corners reach the profile's range (F1.2 behavior
     1.1, 50 km by default), so the map shows what the filter's range receives; about 150 km across without a range;
   - otherwise the whole world. When the location arrives after the map opens (the web app gets its settings after
     the map has a size), the map moves there unless the viewer has zoomed in by then. A view of the whole world is
     never remembered, and a remembered one opens at the location instead, so an early start can't stick.
3. **Home** (a map button, and `H`) returns to the active profile's location. It is hidden when the profile has none.
4. **Fit** (a map button, and `F`) zooms to fit every station currently shown, with a margin. A single station is shown
   at street level, not as close as the zoom allows.

### Navigation

5. Drag to pan; mouse wheel, pinch, or `+`/`-` to zoom about the pointer (keys: about the centre); double-click or
   double-tap to zoom in one step. On a touch screen, two fingers zoom and pan together, keeping the place between
   them under them; lifting them isn't a tap. Arrow keys pan by a tenth of the view. Zoom stops at the provider's minimum and
   maximum levels.
6. Panning and zooming stay at the display's frame rate with 2,000 stations shown, on desktop and in the browser
   (spike 1's budget: tiles, symbols and labels within about 16 ms per frame on the spike machine).
7. The map has keyboard focus when clicked or tabbed to; its focus outline follows the theme (F0.6).

### Tiles

8. **Default provider:** OpenStreetMap's standard tiles. The visible attribution "© OpenStreetMap contributors" links
   to <https://www.openstreetmap.org/copyright> (the provider's requirement).
9. **Tile usage policy** (OSMF tile policy, and each provider's equivalent), as built in spike 4:
   1. the app's own User-Agent from branding; never a library or browser default;
   2. Cache-Control, Age, Expires and ETag honoured, with 7 days when the server says nothing; expired tiles
      revalidated with conditional requests;
   3. stale tiles served only within the server's `stale-while-revalidate` and `stale-if-error` windows (7 days for
      OSM), immediately while revalidating in the background;
   4. at most 4 upstream requests in flight, and one download for concurrent requests of the same tile;
   5. only tiles the map is showing: no prefetching, no pre-seeding, no "download for offline" (region preloading is
      F4.5, from providers that allow it);
   6. a size cap per cache (default 512 MB) with least-recently-used purging.
10. **Where tiles come from**:
    - **Desktop**: an in-process cache (`AprsMap.Tiles`, MIT, no UI) in the user's cache folder: `%LOCALAPPDATA%` on
      Windows, `~/.cache` on Linux, `~/Library/Caches` on macOS, each under `aprsnet/<slug>/tiles`.
    - **Browser**: the gateway's same-origin `/tiles/{provider}/{z}/{x}/{y}.png`, backed by the same cache on the
      gateway, shared by all viewers. It serves only configured providers and valid coordinates, so it isn't an open
      proxy, and passes the browser's Referer through.
11. **Providers are configured on the engine side** (desktop `appsettings.json`, gateway environment):
    `Tiles:Providers:<key>` with a name, URL template (`{z}/{x}/{y}`, optional inverted `{-y}`), attribution text and
    link, minimum and maximum zoom, and image type. The viewer picks one in Settings › Map. A provider the gateway
    doesn't configure can't be used from a browser.
12. While tiles load, the map shows the theme's ground colour, never a checkerboard. A tile that can't be fetched
    leaves its area blank and logs at Debug level; the map keeps working without tiles.
13. **Map contrast** (revised for [#345](https://github.com/APRS-NET/AprsMap/issues/345), proposed 2026-10-21):
    symbols get lost in the tiles' colours (green parks, blue water, yellow roads), so a **Map contrast** button with
    the map's other buttons opens a popover with:
    1. **Map fade**, a slider from 0 to 80 % (in 5 % steps) that fades the tiles toward the theme's ground colour.
       Until the viewer moves it, it follows the theme: none in a light theme, 35 % in a dark one. It replaces the
       three Map brightness steps; a saved Normal, Dimmed or Dark becomes 0, 35 or 60 %.
    2. **Greyscale map**: the tiles without colour, so coloured symbols, tracks and areas stand out.
    3. **Backing behind symbols**: a soft disc behind each station's symbol in the label halo's colour (half as strong
       for a stale station).
    4. **Reset**: back to the theme's fade, in colour, without backing.

    Changes apply as they're made. The same three are in Settings › Map (the fade as Follow the theme or 0, 20, 35,
    50, 60 or 80 %), for the keyboard and screen readers. Only the tiles are filtered, so symbols, labels, tracks and
    the selection keep their theme colours. A provider can offer its own dark tile set, used instead when configured.

### Stations

14. Every station from the station stream (`WatchStationsAsync`, F0.2) with a position is drawn at it, with its APRS
    symbol from APRS.NET (`AprsNet.Symbols`), including overlay characters. A station without a known symbol gets a
    neutral dot.
15. **Symbols are drawn from an atlas** (spike 3): the 188 base symbols are built when the map first shows, overlays
    the first time a packet uses one, and everything is drawn with one call per frame. The atlas is rebuilt when the
    map symbol size (F0.6), the screen scale or the theme changes.
16. **Map symbol size** (Settings › Map, 75–200 %, F0.6 behavior 14) scales symbols and labels together. It becomes
    visible in Settings with this feature.
17. **Labels**: the callsign under each symbol, in a halo that follows the theme. Labels never overlap: when they
    would, the more recently heard station keeps its label (Settings › Map › Labels: All that fit · None). Symbols
    always show.
18. **Selection**: clicking or tapping a station selects it, with a ring in the accent colour, and raises a selection
    event (the details pane is F1.6). Clicking the map's background clears it. Hovering a station shows its callsign
    and how long ago it was heard.
19. **Aging**: a station not heard for 30 minutes is drawn at half opacity; one not heard for 2 hours is removed
    from the map (the engine's expiry is F1.3; until then the map hides it). Both times are settings later (F1.3).
20. Stations, labels and the selection ring use theme tokens (`Color.*`), so they follow the theme and palette (F0.6).
    Text and symbols on the map meet the palette's contrast target against the halo.

### Settings › Map

21. A **Map** section in Settings (F0.6 registry) with: tile provider, map fade, greyscale map, backing behind
    symbols, labels, and map symbol size.

### Accessibility

22. The map isn't usable with a screen reader; the station list (F1.7) is the accessible view of the same stations.
    The map's buttons (Home, Fit, zoom) have accessible names and work from the keyboard.

## Service surface

- **Stations:** `WatchStationsAsync` (F0.2) as is.
- **Tiles:** not an `IEngineService` member, because tiles are HTTP images: a platform service `ITileSource` in
  `AprsMap.UI.Platform` (`GetTileAsync(provider, z, x, y)` and the provider list). Desktop: `AprsMap.Tiles` in process.
  Browser: the gateway's `/tiles` endpoint and `/tiles/providers`.
- **New projects:** `AprsMap.Tiles` (MIT; cache and fetch, `IHttpClientFactory`, `TimeProvider`), and the map control
  in `AprsMap.UI` (`MapView`, hosting Mapsui's core for projection and tile layout, and our own Skia layer for
  stations, as spike 1 found Mapsui.Avalonia doesn't support Avalonia 12).
- **Preferences:** the last view, map fade, greyscale, symbol backing, labels and provider choice are per viewer (`IPreferenceStore`, F0.6).

## APRS.NET dependencies

- `AprsNet.Symbols` for the drawings (already used). No new gap.

## Desktop vs web differences

| | Desktop | Web |
| --- | --- | --- |
| Tiles from | In-process cache, user's cache folder | The gateway's `/tiles`, shared cache |
| Providers | Its own configuration | The gateway's configuration only |
| Drawing | Skia, GPU | Skia in WebAssembly (AOT in Release, decision 1) |

## Acceptance tests

1. The tile cache: freshness from the headers, conditional revalidation (304 renews), stale only within the server's
   windows, 4 in flight, merged duplicate downloads, LRU purge at the cap, the branded User-Agent (fake HTTP handler
   and clock, as in spike 4).
2. The gateway's `/tiles` refuses unknown providers and out-of-range coordinates, passes the Referer, and serves two
   browsers' identical requests with one upstream fetch.
3. Opening position: last view, else profile location fitted to its range, else world; Home and Fit as described.
4. Stations from a scripted stream appear, move, fade at 30 minutes and go at 2 hours (fake clock).
5. Labels never overlap; the more recently heard keeps its label.
6. Selection by click, cleared by background click; the event carries the station.
7. Performance: 2,000 moving stations hold the frame budget on desktop and in the published browser app (benchmark
   from spike 1, run by hand and recorded).
8. Every palette and theme: symbols, labels and selection use tokens; the 200 % render check (F0.6) covers the map's
   buttons and attribution.
9. Map contrast (#345): the slider sets the fade (at most 80 %) and Reset follows the theme again; Settings › Map and
   the button change the same settings; a saved Map brightness becomes its fade; the backing is drawn around a
   symbol only when on.

## Performance check

Acceptance test 7, run by hand on 2026-10-15 with the published browser app (Release) in headless Firefox on the
development machine (1280 × 800). The gateway was fed by `tools/ci/fake-aprsis.py --around 40.0,-105.15 --count N`:
a third of the stations move and each reports every 10 seconds, staggered (about 70 packets a second at 2,000). The
map was dragged continuously for 500 moves, 16 ms apart, with the view about 300 km across, and every
`requestAnimationFrame` timed.

| Build | Stations | Frames a second | Frame time p50 / p95 (ms) |
| --- | --- | --- | --- |
| Interpreted, labels as text | 40 | 59 | 17 / 17 |
| Interpreted, labels as text | 2,000 | 8 | 34 / 417 |
| AOT, labels as text | 2,000 | 35 | 33 / 50 |
| AOT, no labels | 2,000 | 60 | 17 / 17 |
| AOT, labels as cached bitmaps (shipped) | 2,000 | 60 | 17 / 17 |
| AOT, labels as cached bitmaps (shipped) | 40 | 60 | 17 / 17 |

What it took: AOT for Release (decision 1); station changes applied to the map one by one instead of replacing the
whole set on every batch; and each label drawn once into a bitmap, since drawing the halo as text (nine passes per
label) cost more than the tiles and symbols together. Still to do: the same run on the desktop, which needs an
unlocked screen; it draws with native Skia on the GPU, so it is expected to do no worse than the browser.

## Decisions for review

1. **Browser AOT:** spike 1 found AOT about doubles drawing speed, at a download of about 73 MB against 35 MB
   uncompressed (much less with Brotli) and a slower publish. Proposed: AOT on for Release.
2. **Wind barbs** are in F1.4's scope line, but they need the weather decoding of F1.10. Proposed: move them to F1.10.
3. ~~Packet list placement~~: decided 2026-10-15, it is a panel in the F1.0 shell, docked along the bottom by
   default.
4. **Default label policy:** labels that fit (proposed), or labels only for selected and recently heard stations?
5. **Map contrast** (#345, proposed 2026-10-21): a button on the map rather than only in Settings; a fade slider up
   to 80 % replacing the three brightness steps; greyscale and symbol backing off by default; per viewer.
