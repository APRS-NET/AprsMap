# F4.17 SBOM for every release

Status: built for 0.6.0 ([#352](https://github.com/APRS-NET/AprsMap/issues/352)); CycloneDX by the maintainer
(2026-10-21), the rest proposed for review.

## User story

As someone deciding whether to run the app or the gateway, or tracking a vulnerability, I download each release's
software bill of materials and see exactly which packages, at which versions and under which licences, went into what
I'm running, in a standard format my tools read.

## Background: what already exists

- The release workflow (F4.8, F4.15) publishes desktop archives and installers for six runtimes, and the gateway image
  (with the browser app inside) to GitHub Container Registry, all from a release-please tag.
- Package versions are central (`Directory.Packages.props`); every project restores to `obj/project.assets.json`.

## Behavior

1. **CycloneDX JSON** (maintainer, 2026-10-21), spec version 1.6, made with the CycloneDX .NET tool (`cyclonedx`,
   pinned in `.config/dotnet-tools.json`) from each app's own restore, so it lists exactly the packages that app's
   build uses, transitive ones and every `AprsNet.*` included, each with its version, package URL (`pkg:nuget/…`),
   SHA-512 hash and licence (the licence text too when a package ships it as a file).
2. **One SBOM per app** (proposed): the desktop app, the gateway and the browser app, named like the release's other
   files (`aprsmap-v0.6.0-desktop.cdx.json`, `…-gateway.cdx.json`, `…-browser.cdx.json`). One desktop SBOM covers all
   six runtimes: the packages are the same for each, only which native files are copied differs. Each also lists the
   .NET shared frameworks it runs on (`Microsoft.NETCore.App`, and `Microsoft.AspNetCore.App` for the gateway), at the
   version the release is built with, since they ship with it but aren't packages.
3. **The image** gets its own SBOM, made from the pushed image with Syft (`anchore/sbom-action`), so it lists the base
   image's OS packages as well; it's **attested** to the image in the registry (`actions/attest`, signed with
   Sigstore; `gh attestation verify oci://ghcr.io/aprs-net/aprsmap:<tag> --owner APRS-NET` checks it) and attached to
   the release as `aprsmap-v0.6.0-image.cdx.json`. It's made from the linux/amd64 variant (proposed): both
   architectures are built from the same files.
4. **Attached to every release** beside the files it describes, by the release workflow; nothing to do by hand.
5. **Checked**: `tools/ci/check-sbom.py` fails when a file isn't CycloneDX, names no app or version, has a package
   without a version, package URL or hash, has no `AprsNet.*` package, or doesn't list the .NET runtime; packages that
   state no licence are listed as a warning (the SBOM says what each package says). The release runs it before
   attaching; CI runs it on every change (`sbom` job), so a break shows before release day.
6. Locally: `dotnet tool restore && tools/sbom.sh <version> <folder>`.

## Service surface

None: build and release only. Files: `tools/sbom.sh`, `tools/ci/check-sbom.py`, the `sbom` jobs in `ci.yml` and
`release.yml`, and the image SBOM steps in `release.yml`'s container job.

## APRS.NET dependencies

None. (APRS.NET's own packages appear in the SBOM with the licence they declare; `AprsNet.DeviceId` declares a licence
file, carried as text.)

## Desktop vs web differences

| | Desktop | Web (gateway) |
| --- | --- | --- |
| SBOM | `…-desktop.cdx.json`, all runtimes | `…-gateway.cdx.json` and `…-browser.cdx.json`; the image's, attested |

## Acceptance tests

1. `tools/sbom.sh` writes three CycloneDX 1.6 files that pass `check-sbom.py`, with every `AprsNet.*` package the app
   uses and the .NET runtime.
2. `check-sbom.py` fails on a file with no components, no app version, or a package without a hash.
3. The release workflow attaches the three files and the image's, and the image's attestation verifies with
   `gh attestation verify`. (Checked on the first release that carries this.)

## Decisions for review

1. **CycloneDX** (maintainer, 2026-10-21), 1.6, JSON.
2. **One SBOM per app**, not per runtime: the package graph is the same for every runtime.
3. **The .NET shared frameworks listed** as framework components at the build's runtime version.
4. **The image's SBOM from Syft, attested** with GitHub's attestations, from its linux/amd64 variant.
5. **Missing licences warn, not fail**: three third-party packages state none; the SBOM doesn't invent one.
