# F1.16 Extra map views

Status: draft

## User story

As an operator watching several moving stations at once (a race's lead and sweep vehicles, two balloons), I can open
extra map views, each following one station, beside the main map or, on the desktop, in their own windows I can put
on another screen. The stations I'm watching are always received, even when they leave my filter's range.

## Behavior

### Opening and arranging

1. **Watch in a view** (from a station's details, F1.6, the station list's row menu, F1.7, or `W` with a station
   selected) opens a map view that follows that station (F1.7 behavior 8), titled with its name.
2. **Panels**: each extra view is a panel in the F1.0 shell, opened beside the main map. It can be docked, tabbed,
   split or floated like any panel (up to 4 views in all, the main map included). Narrow windows show one view at a
   time with tabs instead.
3. **Desktop windows**: floating a view (F1.0) puts it in its own window, on any monitor. Its place is saved with the
   layout and kept on a screen that exists (F1.0 behaviors 8 and 12). Browsers float views inside the page.
4. Each view has its own zoom and the main map's tile provider and layers. Panning by hand stops following in that
   view only, with **Follow again** on its chip.
5. **Close** (the panel's close button, or Escape inside it) removes it; closing the main window closes its floating
   windows.

### What it changes elsewhere

6. A watched station is added to the APRS-IS filter as a buddy part (F1.2, tracked stations), so it stays received
   when it leaves the range. On a gateway, this follows the F1.2 rule: only with `Gateway:FollowViewers`, or when the
   operator watches it.
7. A watched station's track uses the followed style (F1.5) in every view.
8. **Message-delivered items**: an item sent to me in a message (Phase 2) can open a view automatically (a setting,
   off by default); this behavior arrives with F2.4.
9. Open views are a per-viewer preference, restored on the next start for stations still known.

## Service surface

- No new engine members for the views themselves: they are UI state.
- The watched list joins the map view report to the engine (F1.2 `SetMapViewAsync` gains `watched` callsigns) for the
  buddy part.

## APRS.NET dependencies

- **G04** (via F1.2) for the buddy part. None directly.

## Desktop vs web differences

| | Desktop | Web |
| --- | --- | --- |
| Separate windows | Yes | No (split view and tabs only) |
| Watched stations in the filter | Always | With `Gateway:FollowViewers`, or the operator's own views |

## Acceptance tests

1. Watch in a view opens a following view; up to 4 views; a 5th asks to close one.
2. Narrow layout shows tabs; wide shows the grid; the 200 % render check covers the view chips.
3. Desktop: a view opens in a window and back, and its window placement returns after a restart.
4. A watched station appears in the filter's buddy part and leaves it when the view closes.
5. Panning one view stops only that view's following.

## Decisions for review

1. **Up to 4 views** in all (proposed). Each view costs a frame's drawing, and 4 holds the frame budget on the spike
   machine with 2,000 stations.
