# F1.16 Extra map views

Status: built for 0.6.0 ([#207](https://github.com/APRS-NET/AprsMap/issues/207)) except behavior 8; decisions proposed
2026-10-19 for the maintainer's review. In the UI: Details › Watch in a view, or `W` on the map.

## User story

As an operator watching several moving stations at once (a race's lead and sweep vehicles, two balloons), I can open
extra map views, each following one station, beside the main map or, on the desktop, in their own windows I can put
on another screen. The stations I'm watching are always received, even when they leave my filter's range.

## Behavior

### Opening and arranging

1. **Watch in a view** (from a station's details, F1.6, or `W` on the map with a station selected) opens a map view
   that follows that station (F1.7 behavior 8), titled with its name. Watching a station that already has a view brings
   that view to the front. The station list's row menu (F1.7) gets it when that list has a row menu (proposed: later).
2. **Panels**: each extra view is a document in the F1.0 shell. The first opens beside the main map, splitting its
   space so both show; the next ones open as tabs beside it (proposed). Each can be moved, tabbed or floated like the
   dashboard. Up to 4 views in all, the main map included; a fifth says to close one first (proposed: a message, not
   a question).
3. **Desktop windows**: floating a view (F1.0) puts it in its own window, on any monitor. Its place is saved with the
   layout and kept on a screen that exists (F1.0 behaviors 8 and 12). Browsers float views inside the page.
4. Each view has its own zoom and the main map's tile provider and stations; the first time it finds its station it
   shows about 20 km around it. Panning by hand, or Escape, stops following in that view only, with **Follow again**
   on its chip (or `L`). Until the station is heard, the chip says so. It doesn't report its view for the filter or
   remember it (behavior 6 covers its station).
5. **Close** (the tab's close button) removes it; closing the main window closes its floating windows.

### What it changes elsewhere

6. A watched station is added to the APRS-IS filter as a friend range (`f/CALL/km`, as F1.7's followed station), so it
   stays received when it leaves the range, and leaves the filter when its view closes. On a gateway it counts like a
   browser's followed station (F1.2 behavior 9): always, at most 3 per browser (proposed).
7. A watched station's track uses the followed style (F1.5) in every view.
8. **Message-delivered items**: an item sent to me in a message can open a view automatically (a setting, off by
   default). Not built yet: nothing in F2.4 delivers items in messages.
9. Open views are part of the layout (F1.0, F1.23), so they open again on the next start and with a saved layout; a
   station not heard yet waits until it is.

## Service surface

- No new engine members for the views themselves: they are UI state.
- The watched list joins the map view report to the engine: `MapViewReport.Watched`, for the friend ranges.

## APRS.NET dependencies

- **G04** (via F1.2) for the buddy part. None directly.

## Desktop vs web differences

| | Desktop | Web |
| --- | --- | --- |
| Separate windows | Yes | No (split view and tabs only) |
| Watched stations in the filter | Always | Always, up to 3 per browser |

## Acceptance tests

1. Watch in a view opens a following view beside the map; the same station brings its view back; up to 4 views; a 5th
   says to close one.
2. The view keeps its station centred as it moves; Escape stops following there only, `L` follows again.
3. Views come back with the layout after a restart.
4. A watched station appears in the filter as a friend range and leaves it when the view closes; a browser's count up
   to 3.

## Decisions for review

All proposed (2026-10-19), built as described so they can be tried:

1. **Up to 4 views** in all. Each view costs a frame's drawing, and 4 holds the frame budget on the spike machine
   with 2,000 stations.
2. **Opened from Details and `W`**; the station list's row menu later.
3. **Beside the map**, splitting its space for the first view, tabs for the next.
4. **A message, not a question,** for a fifth.
5. **Saved with the layout**, rather than as a separate preference.
6. **On a gateway, watched stations count like a followed one**, up to 3 per browser.
