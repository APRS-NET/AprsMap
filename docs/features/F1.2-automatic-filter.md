# F1.2 Automatic filter

Status: built ([#73](https://github.com/APRS-NET/AprsMap/issues/73)); revised 2026-10-20 at the maintainer's request:
a 50 km default range, **the map no longer changes the filter**, filter circles on by default, Home fitted to the
range, and the automatic filter said when adding APRS-IS (behaviors 1.1, 1.2, 4, 6, 7). Changing the filter by hand
(adding and removing parts) is for later; until then the default range is 50 km.

Built: the engine half. `FilterComposer` builds the filter with APRS.NET's terms from my range (the profile's new
`RangeKm`, 50 by default since 2026-10-20 (150 before), 0 for none), the map views reported with `SetMapViewAsync` (a range around each view that
my range doesn't cover, up to 1,000 km, at most 8), followed stations (`f/CALL/km`) and the profile's own text, which is
now added rather than replacing the rest. With no part and a range, it is `m/<range>`. A view only counts when it moved
a quarter of its radius or changed size by a quarter. Sends go without a new login, at most one every 5 s, with changes
made meanwhile merged. `EngineStatus.Filter` says what was sent. On a gateway a browser's map part counts only with
`Gateway:FollowViewers` (capped at 500 km) and its followed station always, until it disconnects (behaviors 1–5, 8, 9).
Then the UI half: the map reports its view 2 s after it stops moving, and following at once; the profile editor offers
the range (none, 25–500 km); the filter in use is in the connection's tooltip and under Settings › Profiles; and Settings ›
Map's "Show the filter's ranges on the map" draws each range part as a dashed circle in the accent colour, from
`EngineStatus.FilterAreas` (behaviors 6, 7). Decisions 1 and 2 as proposed. Tracked stations (`b/`) wait for F1.16.

## Behavior

### The parts

1. The engine builds the APRS-IS filter from parts, with APRS.NET's typed filter builder (G04):
   1. **My range**: a range around my location (F1.13), with the profile's **range** setting (default 50 km, the
      maintainer's choice on 2026-10-20, 150 before; 0 means no range part, as an IGate wants). New profiles get the
      default; a saved profile keeps its range;
   2. **Map view: not part of the filter** (the maintainer's choice on 2026-10-20). Panning and zooming change what
      the map shows, not what APRS-IS sends; the app doesn't report its view. The engine still accepts a map part in
      a view report (a range around the view's centre, half its diagonal, capped at 1,000 km), kept for a later filter
      editor and for `Gateway:FollowViewers`, but nothing sends one now;
   3. **Followed station**: while the map follows a station (F1.7), a friend range around it (`f/CALL/km`) with the
      same radius as my range;
   4. **Tracked stations**: stations pinned to extra map views (F1.16) as a buddy list (`b/CALL1/CALL2…`);
   5. **The profile's own filter text**, appended as typed (F0.8), for anything else.
2. With no location, no map view and no own filter text, the filter is `m/<range>`, around the callsign's last known
   position on APRS-IS (as the stand-in does now).

### Updating

3. The filter is recomputed when any part changes, and sent with `SetFilterAsync` (F1.1), never with a new login.
4. Map movements don't send anything (behavior 1.2). A view report from elsewhere (a later filter editor, or a
   gateway's viewer with `FollowViewers`) still counts only when its map part differs enough (centre moved more than a
   quarter of the radius, or radius changed by more than a quarter).
5. Sends are limited to one every 5 s; a change inside that window waits and is merged with any later one.

### Seeing it

6. **Filter circles** (Settings › Map, and a map layer toggle; **on by default** since 2026-10-20, so the area
   received shows): each range part as a faint circle in the accent colour, so it's clear what the server is sending.
   The circles use theme tokens and the palette's contrast (F0.6). A viewer who turned them off keeps them off.
7. The current filter text appears in the connection's tooltip and in Settings › Profiles for the active profile, for
   anyone who wants to check it. **Adding or editing APRS-IS** (Settings › Sources, and first run's step) says what
   the automatic filter already receives, beside the box for the source's own text: the profile's range around its
   location (or where APRS-IS last heard it), and stations followed or watched, saying that moving the map doesn't
   change it; and the filter in use once there is one.

### On a gateway

8. One gateway has one APRS-IS login, but every browser has its own map view. By default, a gateway's filter uses only
   **my range, followed and tracked stations and the profile's text**, not viewers' map views, so an anonymous
   viewer can't widen what the station receives.
9. **`Gateway:FollowViewers`** (off by default) adds viewers' map parts (none are sent since 2026-10-20, behavior 1.2): one range part per connected viewer, up to 8
   (APRS-IS accepts at most 9 range parts, and my range is one), each capped at 500 km, dropped when the viewer
   leaves; the most recently moved views win. For a club where everyone may steer the station.

## Service surface

- The UI reports its map view to the engine: `SetMapViewAsync(centre, radiusKm)`, debounced as in behavior 4. On a
  desktop it is the window's map; on a gateway it is ignored unless `Gateway:FollowViewers` is on.
- `EngineStatus` gains `Filter` (the text currently sent) for behavior 7.
- The profile gains `RangeKm` (default 50; 150 before 2026-10-20).

## APRS.NET dependencies

- **G04, typed filter builder** (range, friend range, buddy list, my range, raw parts): delivered (`0.2.0-alpha.2`,
  `AprsNet.Filters`); the stand-in already uses it.
- **G08, geodesy**: the view's radius from its corners, and the 1,000 km cap.
- **G03** (delivered, `0.1.0-alpha.17`): `SetFilterAsync` on the live connection, kept across reconnects.

## Acceptance tests

1. With a location and the default range: `r/<lat>/<lon>/50` plus the profile's text; with range 0, no range part.
2. Panning and zooming the map send nothing and leave the filter as it is.
3. Following a station adds `f/CALL/<range>`; stopping removes it. Tracked stations add `b/CALL1/CALL2`.
4. Sends are at most one per 5 s and never trigger a new login (fake connection counts logins).
5. On a gateway without `FollowViewers`, a browser's map view changes nothing; with it, up to 8 viewer parts, each
   capped, and never more than 9 range parts in all.
6. Filter circles draw each range part in every palette, and are on for a new viewer.
7. At Home with a 50 km range, the map's report stays within the range, so the filter is just `r/<lat>/<lon>/50`.
8. Adding APRS-IS says what the automatic filter receives and the filter in use.

## Decisions for review

1. **Gateways don't follow viewers' maps by default** (behavior 8). Proposed: yes, because anonymous viewers would
   otherwise steer the station's feed.
2. **The 1,000 km cap** on the map part. Proposed: yes; beyond that a filter returns most of a continent, and the
   full feed is better asked for explicitly with the profile's own filter text. Moot since 2026-10-20: the map isn't
   part of the filter (decision 3).
3. **The map doesn't change the filter, and the default range is 50 km** (the maintainer, 2026-10-20), until the
   filter can be changed by hand.
