# F1.19 Housekeeping

Status: built ([#128](https://github.com/APRS-NET/AprsMap/issues/128)) for stations, stale stations, tracks and the
packet history, in Settings › Data with the main menu's Clear data… opening it. Telemetry joins with F1.11, and Clear
map cache (behavior 4) isn't built yet. Decision 1 as proposed. The packet history's clear reaches other viewers
through `EngineStatus.PacketHistory`, which counts clears.

## User story

As an operator, I can clear out what the station has collected (all stations, old tracks, the packet history,
telemetry) to start fresh, for example before an event or after testing, without restarting the app and without
losing my settings.

## Behavior

1. A **Clear** menu (in the main menu, and Settings › Data) offers, each with a count of what will go:
   1. **Stations**: every station, object and item, with their tracks, weather and telemetry;
   2. **Stale stations**: only those past the stale time (F1.3);
   3. **Tracks**: every history, keeping each station's latest position (F1.5);
   4. **Packet history**: the held packets (F1.8);
   5. **Telemetry**: reports and definitions (F1.11).
   Later phases add messages, bulletins and saved texts to the same menu.
2. Choosing one asks for confirmation ("Clear 2,140 stations?") with the count, because clearing can't be undone;
   the confirmation is a dialog that works from the keyboard and with a screen reader.
3. After clearing, viewers' maps and lists update at once (the removals are streamed, F0.2), and new packets fill the
   store again as they arrive.
4. Clearing never touches settings, profiles, preferences or the tile cache. The tile cache has its own **Clear map
   cache** in Settings › Map (desktop; on a gateway it is the operator's).
5. On a gateway, clearing is operator-only (the settings gate), since it clears the store for every viewer.

## Service surface

- New `Task<int> ClearAsync(ClearScope scope)`: clears and returns the count; gated like settings on a gateway.
- New `Task<ClearCounts> GetClearCountsAsync()` for the counts in the menu.
- `ClearScope`: `Stations`, `StaleStations`, `Tracks`, `Packets`, `Telemetry` (extended in later phases).

## APRS.NET dependencies

None.

## Desktop vs web differences

| | Desktop | Web |
| --- | --- | --- |
| Clear | Anyone | Operator only |
| Clear map cache | The desktop's cache | The gateway's shared cache, operator only |

## Acceptance tests

1. Each scope clears what it says and nothing else; counts match; settings are untouched.
2. Removals stream to every viewer; new packets fill the store again.
3. The confirmation shows the count and works by keyboard; Cancel clears nothing.
4. On a read-only gateway, `ClearAsync` is refused with `gateway.operator-only`.

## Decisions for review

1. **Confirmation instead of Undo** (proposed): unlike a profile delete, a clear can't be undone cheaply (the store may
   hold 50,000 entries), so it asks first.
