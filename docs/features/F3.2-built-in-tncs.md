# F3.2 Radios' built-in TNCs

Status: spec'd for 0.5.0 ([#242](https://github.com/APRS-NET/AprsMap/issues/242); maintainer request, 2026-10-18).
Builds on KISS over serial (F3.1 behavior 1.2, [#177](https://github.com/APRS-NET/AprsMap/issues/177)). Waits on G14
([APRS.NET#249](https://github.com/APRS-NET/APRS.NET/issues/249)): KISS setup is in review, the APRS-mode reader and
typing over an open connection are still to do.

## User story

As an operator with a radio that has a TNC inside, such as a Kenwood TH-D72A on its USB cable, I plug it in and it
works: either it listens in the radio's own APRS mode with no setup, or the app switches it into KISS so it receives and
sends, and when something goes wrong I can type to the TNC myself without unplugging anything.

## Background

- A TH-D72A's TNC has two modes the computer can use. In **APRS mode** (APRS12) it prints each packet it hears as a
  TNC-2 text line and keeps working as an APRS station on its own (display, beacons, message acks); nothing can be sent
  from the computer. In **packet mode** (PACKET12) it takes commands at a prompt, and `KISS ON` then `RESTART` puts it
  in KISS, where it receives and sends KISS frames. A power cut leaves KISS off. (APRS.NET's TNC guide and its
  validation run on the maintainer's radio, 2026-10-17.)
- Today a KISS source that gets text says "TNC isn't in KISS mode" (F3.1 behavior 13) and the operator has to fix the
  radio by hand, with another program.

## Behavior

### Two ways to connect a radio

1. **Settings › Sources › Add a source** offers, beside KISS over serial (F3.1 behavior 1.2):
   1. **Radio in APRS mode (receive only)**: a serial port and speed, as for KISS over serial. No TNC setup.
   2. KISS over serial with a **TNC type** (behavior 4).
   The kind's help says which to pick: APRS mode to listen without changing anything on the radio; KISS to send too.

### Radio in APRS mode (receive only)

2. The source reads the radio's text lines into packets (APRS.NET's APRS-mode reader). NMEA sentences the radio prints
   when its GPS output is on, and lines cut short or run together, are skipped and counted, never read as wrong
   packets. Packets are heard by this station (F3.1 behavior 8) and go through the same store and lists.
3. It **never transmits**: it has no TX enabled checkmark, no Send via entry and no Send position now. It reconnects,
   warns when quiet and lists ports as KISS over serial does (F3.1 behaviors 4, 5, 13).

### KISS with a TNC type

4. A KISS over serial source has a **TNC type**, under "More":
   1. **Plain KISS** (the default): the TNC is in KISS already; nothing is sent to set it up.
   2. **Kenwood TH-D72** and any other type APRS.NET knows (`TncSetup.Known`).
   3. **Custom**: an enter script and a leave script in APRS.NET's script form, one step a line: `send TEXT`,
      `bytes HEX`, `expect 3s TEXT`, `pause 500ms`. Checked when saved (`settings.source.tnc-script-invalid`).
5. With a type other than Plain KISS, the source **switches the TNC into KISS** each time it opens the port, again when
   the TNC starts sending text (a power cut left KISS off), and **out of KISS** when it closes. The pill says
   "Direwolf: switching the TNC to KISS" while it runs.
6. If switching fails, the pill shows APRS.NET's reason in the warning colour, with its hint as the tooltip ("Switch the
   radio's TNC to packet mode (PACKET12) first"), and the source keeps retrying with its usual wait.
7. Running the TNC type's scripts sends nothing on the air, so it needs no licence: it's part of opening the source, for
   listening and sending alike.

### Typing to the TNC

8. A serial KISS source's pill menu has **TNC commands…**, which opens the Source console (F1.28) on that source with
   its command line showing. The port stays open: commands go over the source's own connection.
9. Opening the command line puts the source in **manual mode** (APRS.NET's `BeginManual`); its pill says "Direwolf:
   manual". While it's on, the automatic switching of behavior 5 holds off, so it doesn't fight the person typing; the
   "isn't in KISS mode" warning still shows. Closing the command line, or 10 minutes with nothing sent, ends it, and the
   source carries on as before (switching into KISS again if it has a type and gets text).
10. The command line has:
    1. **Enter KISS** and **Leave KISS**: the TNC type's scripts, run over the open connection (for Plain KISS and a
       TNC with no type: Leave KISS only, the standard KISS exit frame);
    2. a line to type a command, sent with a carriage return; and a **Bytes** choice to send hex instead.
    What the TNC answers shows in the console as it arrives.
11. **Typed commands need a licence.** At a TNC's prompt some commands transmit (`ID`, `CONV`, `K` on TNC-2 style
    TNCs), and in KISS mode bytes sent raw go on the air as a frame. So the typed line and Bytes need a licensed profile
    without Disable TX (F2.1 behavior 4.1, 4.2: `transmit.not-licensed`, `transmit.profile-disabled`); the line says so above
    it, in words: "Some commands make the radio transmit." The Transmit switch isn't required: this is setting the TNC
    up, not operating the station. Enter KISS and Leave KISS are always allowed (behavior 7).

### On a gateway

12. The TNC type, the scripts and the command line are the operator's: changing a source has the settings gate (F0.4),
    and the command line is operator only (`gateway.operator-only`, F2.9's signed-in operator once built).

## Service surface

- `SourceKind` gains `AprsTextSerial` (behavior 1.1). Serial sources use F3.1's port and speed settings.
- `SourceSettings` gains `TncType` (`null` for Plain KISS, an APRS.NET setup id such as `th-d72`, or `custom`),
  `EnterScript` and `LeaveScript` (custom only).
- `IEngineService`:
  - `GetTncTypesAsync()` → the known types (id, name) for the picker;
  - `SetTncManualAsync(sourceId, bool on)` (behavior 9);
  - `SendTncCommandAsync(sourceId, TncCommand)`: a line, hex bytes, or `EnterKiss` / `LeaveKiss` (behaviors 10, 11).
- `SourceStatus` gains `Manual` and `SettingUp`; a failed setup is a `kiss.setup-failed` error with the hint as an
  argument.
- Error codes: `kiss.setup-failed`, `kiss.not-manual` (a command outside manual mode),
  `settings.source.tnc-script-invalid`.

## Desktop vs web differences

| | Desktop | Web (gateway) |
| --- | --- | --- |
| Where the radio plugs in | This computer | The gateway's host (`--device`, F3.1 behavior 12) |
| TNC type and scripts | Anyone who can change settings | The operator |
| Command line | A licensed profile | The operator, with a licensed profile |

## Acceptance tests

1. A fake serial port replaying a recorded APRS-mode transcript (GPS sentences replaced) gives the expected packets,
   heard by this station; the cut lines and NMEA sentences are skipped; the source has no TX enabled checkmark.
2. A fake TH-D72 that answers the setup script switches into KISS when the source opens, and out when it closes; after
   it starts sending text again, it is switched back with no one stepping in.
3. A fake TNC that never answers the expected prompt leaves the pill showing the reason and the hint, and the source
   retrying.
4. With the command line open, text from the TNC doesn't trigger the automatic switch; Enter KISS switches it, and
   packets then arrive on the same connection without a reopen; closing the command line ends manual mode.
5. An unlicensed profile can press Enter KISS and Leave KISS but the typed line and Bytes are refused with
   `transmit.not-licensed`; a licensed one sends them.
6. A custom script with an unknown step is refused when saved, with `settings.source.tnc-script-invalid`.
7. On a gateway, every command is refused for a viewer with `gateway.operator-only`.
8. Manual, on the maintainer's TH-D72A: APRS mode receives with no setup; the TH-D72 type switches it into KISS and
   back; in PACKET12 with KISS off, Enter KISS from the command line brings packets in.

## Decisions for review

1. **APRS mode as its own source kind** (proposed), rather than a TNC type of KISS over serial: it never sends, needs no
   setup and reads text, so it shouldn't offer anything KISS offers.
2. **Setting up the TNC needs no licence; typed commands do** (proposed): the type's scripts only switch modes, while a
   typed command can key the radio.
3. **The Transmit switch isn't needed for typed commands** (proposed), only the licence: it's setup, and the switch is
   for operating the station.
4. **Manual mode ends after 10 minutes with nothing sent** (proposed), so a forgotten command line doesn't keep the
   automatic switching off.
5. **No switching between APRS and packet mode from the computer** (as APRS.NET#249): it's one step on the radio's
   menu, and the hint says so.
