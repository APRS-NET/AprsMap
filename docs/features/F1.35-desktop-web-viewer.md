# F1.35 Desktop web viewer

Status: built for 0.6.0 ([#364](https://github.com/APRS-NET/AprsMap/issues/364)); decisions 1–3 by the maintainer
(2026-10-24), the rest proposed for review. In the UI: Settings › Web viewer (desktop only).

## User story

As a desktop user, I let a browser on this computer, or my phone or tablet on the home network, watch my station: the
map, the stations, the packets and the messages heard, without running a separate gateway. Nothing in the browser can
change my station or transmit.

## Background: what already exists

- The gateway (F1.14) serves the browser app and the engine over SignalR; viewers there are read-only unless signed in
  as the operator (F2.9), with home privacy (F1.26 behavior 11), viewer limits and a call rate (F1.14 behaviors 3, 4).
- The desktop app runs the engine and the UI in one process, with no web server.

## Behavior

1. **The browser app comes with the desktop app** (maintainer, 2026-10-24): every desktop archive and installer carries
   it in `browser` beside the program, so sharing works offline. A build without it (a development build) says so and
   can't share; `WebViewer:WebRoot` points one at a browser app built by hand.
2. **Settings › Web viewer › Share to browsers**, off by default, kept with the user's preferences, so it shares again
   when the app starts.
3. **Who can connect**: **This computer only** (the default) or **Devices on my network**, and the **port**, 8090 by
   default (beside a gateway's usual 8080), from 1024 to 65535. Changes take effect with **Apply**, which restarts the
   viewer.
4. While sharing, the section says how many browsers are watching and lists the **addresses to open**, each with
   **Copy**: `http://localhost:8090/`, and on the network each of the computer's IPv4 addresses.
5. **Your location for viewers** (proposed): Exact (the default), Grid square only, or Hidden, as a gateway's home
   privacy.
6. **View only** (maintainer, 2026-10-24): browsers see what the desktop sees but can't sign in, change settings or
   transmit, by the gateway's own viewer rules. **Operator sign-in** from a browser is scoped for later (F1.36).
7. **A port in use** says so and suggests another; any other failure says what the system said. Neither stops the app.
8. The first time on the network the system may ask to allow the app; the section says so, and that sharing is plain
   HTTP, for networks the user trusts.

## Service surface

- No new `IEngineService` member: browsers use the existing hub, served by the desktop.
- `AprsMap.Server` (new, AGPL): the gateway's server parts (hub, browser app's files, tiles, viewers, home privacy,
  operator sign-in) moved out of the gateway so both hosts use them, with `WebViewer.StartAsync` for the desktop.
- `IWebViewerHost` (UI platform service): the desktop's; null in the browser, which hides the section.

## APRS.NET dependencies

None.

## Acceptance tests

1. Started around an engine, the viewer serves the page, `/source`, the tile providers and the hub; a browser's status
   counts it as a viewer.
2. A browser can only watch: its settings are read-only, and saving, Transmit, sending a position and the update status
   are refused.
3. A taken port fails to start; on the network, the addresses include the computer's IPv4 addresses.
4. Settings: switching on shares on this computer and lists the address; the network, port and location apply together;
   a bad port is refused; a taken port is said; a build without the browser app can't share; Copy copies an address.
5. The real browser app, served by the viewer around a desktop-like host, passes the browser smoke test (checked by
   hand, 2026-10-24).

## Decisions for review

1. **Bundled** in every download (maintainer, 2026-10-24). Measured 2026-10-24 on linux-x64: the browser app is 38 MB
   unpacked (19 MB zipped; the `.br` copies left out, since browsers ask for Brotli only over HTTPS), and the ASP.NET
   Core runtime adds 24 MB to the program (107 → 131 MB). About 60 MB more unpacked, roughly 30 MB more per download.
2. **View only now**, operator sign-in later as F1.36 (maintainer, 2026-10-24).
3. **The gateway's server code shared**, not copied: `AprsMap.Server`.
4. **Off by default, this computer only by default, port 8090** (proposed).
5. **Exact location by default** for viewers (proposed): a home network's own devices; Grid and Hidden offered.
6. **Plain HTTP** (proposed): certificates for a LAN address can't be trusted without setup; said in the section.
