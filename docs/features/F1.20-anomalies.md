# F1.20 Anomaly flags

Status: built ([#127](https://github.com/APRS-NET/AprsMap/issues/127)). Built: Invalid (behavior 2) and the track
flags (1) from APRS.NET's `TrackAnalysis` (G24, `0.3.0-alpha.2`), checked for each station position report against its
last 30 minutes of reports (at most 50), with APRS.NET's defaults (2-minute repeated position, 30-minute late copy, 1 s
rapid repeat) and 1,000 km/h for anything not in the aircraft symbols, 3,000 km/h for those (decision 1, with F1.5's
track joining every point); each flag counted per station over the last hour (3); in the details' Problems section
with its count and latest example in words, with its figures (5); a station-list marker and the "has problems" View
filter condition (6, 7); and on the packet list a broken-path marker naming the flags, an explanation line per flag in
the expanded row, and the Issues only filter finding them too (4, decision 2). Objects and items aren't checked: others
move them. On 3 minutes of real traffic around Kansas City, 4 of 62 position reports were flagged, all repeated positions
from fixed stations beaconing more often than every 2 minutes.

## User story

As an operator who helps others get their stations right, I can see which stations are misbehaving: resending the
same position over and over, jumping impossibly far, beaconing faster than makes sense, or sending malformed packets.
The packets and the stations are flagged, so I can find the problem and tell the owner.

## Behavior

### The flags

1. For each position report, the engine asks APRS.NET's track anomaly analysis (G24), with the station's recent
   history (F1.5), for these flags:
   1. **Repeated position**: the same position resent after the duplicate window (a tracker without a fix, or a fixed
      station beaconing too often);
   2. **Impossible speed**: the jump from the previous position implies more than the limit (1,000 km/h; 3,000 km/h
      for aircraft and balloon symbols; F1.5 behavior 3);
   3. **Rapid repeat**: two packets from the station less than a second apart that aren't duplicates;
   4. **Time backwards**: a timestamped report older than the previous one;
   5. **Ambiguity jump**: the position moves because its ambiguity changed, not because the station did.
2. **Invalid**: a packet with parse issues (F1.8 behavior 3) is flagged too, from `AprsPacket.Issues`.
3. Each flag counts per station over the last hour.

### Where they show

4. **Packet list** (F1.8): a marker per flag on the packet's row, with its name and an explanation in the tooltip and
   the expanded row; an **Anomalies only** filter.
5. **Station details** (F1.6): a Problems section listing each flag with its count in the last hour and the latest
   example ("Impossible speed: 4,820 km/h from the previous position, 3 times in the last hour").
6. **Station list and view filter**: a "Has problems" view condition (F1.9) and a marker on the station's row.
7. Markers use a shape and a name, never colour alone, and the palette's warning colour (F0.6).

## Service surface

- `PacketView.Flags` (F1.8) gains the anomaly flags.
- `StationDetail` (F1.3) gains `Problems`: flag, count in the last hour, latest example (with arguments as an
  `EngineError`-style code, `anomaly.<flag>`, translated in the UI).
- `StationFilter` (F1.9) gains `HasProblems`.

## APRS.NET dependencies

- **G24, track anomaly analysis**: everything except Invalid. Until it ships, only Invalid is flagged.
- Parse issues (`AprsPacket.Issues`): delivered.

## Desktop vs web differences

None.

## Acceptance tests

1. Synthetic tracks raise each flag once and only once; normal tracks raise none (after G24).
2. A malformed corpus line is flagged Invalid now.
3. Counts are per station over a sliding hour (fake clock).
4. Markers and explanations show in every language and palette; the filters find flagged packets and stations.

## Decisions for review

1. **Speed limits** (built): 1,000 km/h, or 3,000 km/h for aircraft and balloon symbols. F1.5 joins every point of a
   track, so nothing is left unjoined; the flag says where a jump is impossible.
2. **One "Issues only" filter** (built) for parse issues and track anomalies together, rather than a separate
   "Anomalies only", so one switch finds every packet with something wrong.
