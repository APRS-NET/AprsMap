# F0.10 Start over

Status: built ([#81](https://github.com/APRS-NET/AprsMap/issues/81))

## User story

As someone trying the app (or testing it), I can wipe what it has stored and go through first-run setup again,
without hunting for its settings folder or clearing my browser's site data. Deleting a single profile already exists
(F0.8, with Undo).

## Behavior

1. **Settings › Data** has **Reset the app…**, under a "Start over" heading that says what it deletes on this platform.
   Sections are now Profiles, Appearance, Data, About.
2. It asks first, in place: "This can't be undone. Delete it all?", with **Delete everything** and **Cancel**. Nothing
   is deleted before the confirmation.
3. **Desktop:** deletes every station profile and setting (`settings.json` and copies set aside), this viewer's
   appearance and panel layout (every other `*.json` the app keeps in its settings folder), and the packets and
   stations received. Files of other kinds in the folder are left alone. The engine disconnects and the first-run
   wizard opens, without restarting the app. Defaults from `appsettings.json` (`Engine:Callsign`) aren't applied
   again until the next start, so the wizard shows.
4. **Browser:** deletes what this browser keeps for the app (every `localStorage` key under the product's prefix:
   appearance and layout) and reloads the page. The gateway's station profiles are shared by every viewer, so
   deleting them is a separate tick, **Also delete the gateway's station profiles (for every viewer)**, off by default
   and offered only when this browser may change the gateway's settings (F0.4's gate). On a read-only gateway only
   this browser's data can go.
5. If the engine refuses (a gateway that stopped allowing changes), the reason shows in the confirmation and nothing
   on the device is deleted.
6. **`--reset-all`** at start-up on the desktop does the same before the engine reads its settings, next to
   `--reset-layout` (F1.0).

## Service surface

- `IEngineService.ResetSettingsAsync()`: deletes the stored settings (`ISettingsStore.DeleteAsync`), clears profiles,
  received packets and stations, and reconnects into the not-set-up state. On the gateway it has the same gate as
  `SaveSettings` (`gateway.settings-read-only`).
- `IPreferenceStore.ClearAsync()`: deletes the viewer's own preferences.

## APRS.NET dependencies

None.

## Desktop vs web differences

| | Desktop | Web |
| --- | --- | --- |
| Deletes | Profiles, settings, appearance, layout, received data | This browser's appearance and layout; the gateway's profiles only if ticked and allowed |
| Afterwards | First-run wizard, no restart | Page reloads |
| Start-up option | `--reset-all` | — |

## Acceptance tests

1. Desktop: confirm deletes the settings and preferences, clears the packet list and opens the wizard; Cancel deletes
   nothing.
2. Browser: without the tick the engine isn't reset; with it, it is; the page reloads either way.
3. On a read-only gateway the tick isn't offered, and the hub refuses `ResetSettings`.
4. The file stores delete only their own files (`settings.json` stays for the engine to delete; other files stay).
